# 智能体并不神秘：提示词、工具、状态机

这里简单复述一下我对智能体的理解。AI 类项目一定是未来的趋势，不只是接单。水猫组长转述过一条微信里的视频：智能体方面的需求很大。假如你是建筑专业，学生可能需要 AI 帮他们出专业建筑稿、做渲染，渲染可以用生图模型；医疗专业的企业需要企业级工作流——我对接过学校的导师，前段时间也有群友接过类似的单，单子很大，及时性和专业性都很强，性能优化并不简单。做硬件的，可能需要能帮你画电路板、分析相关东西的智能体。每一个领域和 AI 结合都是趋势，很多企业要走这个方向，AI 也确实在赋能很多东西。

## 两个误区，以及蛋白质折叠

跟硬件结合，常见分成两种。一种是写程序去指挥特定硬件完成职责；另一种是通过硬件去训练一个微小的 AI 模型。前段时间有一场生科和 AI 结合的竞赛，主题是训练模型，指导医生合成药物，让 AI 分析它适配什么样的病毒受体，再相互结合。过去这要大量实验数据和科研人员去试，或靠简单知识推断，效果不好。可以让大模型学习受体、配体这些数据，自己分析该怎么做。

更经典的例子是 AlphaFold 预测蛋白质。高中生物里，蛋白质由氨基酸按模板合成，理论上该有算法算出折叠后的最终结构。实际结构远比课本复杂，一共四级：不只是肽链，还有氢键，链状结构盘曲折叠，多个折叠再在力的作用下形成体积、形状都不同的立体分子。其中一个点、两个氨基酸位置错了，结构和功能就可能完全不同。靠人手工算，做不出来。人们才去找程序自动计算，渲染成更真实的结构，再拿实验比对：测最终结构的物理性质，用仪器测肽链之间的距离和特定形状，判断预测和真实是否一样。整套程序就是模型训练。大语言模型、视频模型，道理类似。医学里实践最多：给 AI 成千上万张片子，让它自己结合、训练一套自计算的体系，分清每张片子是干什么的。这叫智能，更准确的名字是一套特定领域的模型。

## 新词很多，本质很少

目前很多东西都刚兴起。Skills 火了，是因为 Anthropic 命名了一套规范叫 Skills，发现很好用，再加上一些商业化的机制——搞商业的人应该能分析出门道。MCP 也是按他们定义的。现在名词很多：Agent、Prompt Engineering、Context Engineering，以及很火的一套智能体框架 ReAct。说的都是很简单的事，没有太多技术含量，不过有人给一套范式起了名，借着契机火了，大家就这么叫。它没有那么神道。

Skills 本质上就是一套提示词体系。我们当时在企业内部，顶尖工程师早就做过类似的东西，甚至做成了产品。Skills 这套名字发明之前就有：以卡片为基准的大型工作流，那时候基本还没有 AI 驱动的工作流平台。项目很早期，做了不少后来被证明是趋势的东西，也引过投资，但没有火，没能力让很多人知道、使用、评价。内部就算有自己的好标准，也无法被更多人认可。所以很多词，只是大多数人接受之后的约定俗成。

## Agent 就是输入、输出，加上工具标签

Agent 的本质，是一套 AI 调用工程。最简单也最通用的智能体：一段系统提示词，一次输入，一次输出。一次 API 调用，输入输出很明确。它怎么变成智能体？

输入里可以注入特定的词。调用之前通常会有提示词，比如 you are a helpful assistant——你是能帮上忙的。这就是在引导往后的输出一定是帮忙、有用的，而不是莫名其妙的话。为什么叫工程？因为话说多了、长程任务一跑，它就会偏移。前段时间企业里有位老师跟模型对话，说到一半突然蹦出「今天中午吃点啥」，太逗了，我到时候把截图发过去。这是注意力机制。我们不必把问题想得过于复杂，大体上可以用最简化的思路做一套机制，对应到更有价值、很多地方优化得比想象更好的东西。这是那天那位前辈讲的，背后还有一套，有机会再复述。那块比较复杂，这里不展开。

一次 AI 调用就是输入和输出。输入是提示词，输出是什么？Codex 本质上是多次调用 AI，每一次仍是输入和输出。它为什么能发现你电脑里有什么？因为它调用了终端命令行，去执行指令、查看东西。这里要引入第三个概念：工具。工具本身就是输出里的一环。

它想调用技能，本质是什么？系统提示词里规定：我们目前有很多 Skills，A 干什么、B 干什么、C 干什么。模型知道大概干什么；如果当前任务需要，或 Skill 能做得更好，就在输出里给出标签，例如 tool 等于某个 Skill 的 id，其它不管，输入完停止。这就是标签。网站或代码把它解析掉，唤醒工具，把该 Skill 的上下文再次塞进提示词：刚刚模型思考过的所有东西，加上这段 Skill，做成一整段新上下文。每次新增一个 Skill，就是在系统提示词里再插一段名称和说明。这一整套叫提示词工程，没有什么神秘的。

加载完 Skill，模型继续根据内容分析。假如 Skill 说要写一个 HTML 文件，系统提示词里又规定：写代码就再输出标签，比如 tool 等于 writing，标签里夹代码。于是模型取巧地输出一个标签加一堆 HTML，工具再把它解析成真正的写文件——用 Python 举例，就是把这一串写进文件夹并保存。模型只不过调用了这个工具，工具是被我们解析的。

想给 AI 增加图片理解？那其实不是工具。上下文可以拼接，拼的过程中把图片放上去就行。模型「输出图片」，是把输出文字变成输出图片，同样不神秘。若希望它输出公式、数学表达式，一般用 KaTeX：只要输出美元符号，中间夹 `a_1 = 1 \times 2` 这种能打出来的东西，就会被渲染成带下标的公式。这是输出格式的渲染，和调用工具并不相同。但也可以用同一套表示：加标签。比如输出完毕后给用户三个追问，就在系统提示词里说：若还有可追问的，用 question 这类标签列出来。模型只是输出这个结构，系统解析成三个按钮。

这里还有先后顺序。模型刚被训练出来时，输出结构化内容效果可能不好，但能输出，就可以用刚才的机制调用工具。后来再训练，越来越多模型支持。Agent 能力升级，背后往往指一件事：带标签的结构输出变得更好、更稳定。这个时候整套东西才能跑起来。

## 钩子、状态机、最大调用次数

除去这些，还有两个很重要：hook（钩子），以及状态机。状态机一直在监控：AI 可以无限调用工具，直到它发现不用再调，对话停止。这是一套自洽的系统，让模型自行判断该不该继续。智能体之所以叫智能体，是因为它能调动这么多工具，不断调用去解决用户的问题，直到没有工具可调就停止。状态机监测的是：你目前处在什么状态。

钩子呢？调用工具时，检测到标签，就通过 hook 拉取工具内容。你也可以自定义：模型输出完一些内容之后，自动再启动这个钩子——比如总结刚才的输出，做成一小段 summarize。Codex、扣子里，任务执行完等几秒，下面出现一段 recap，简短介绍刚才干了什么，就是钩子。定时任务、cron 任务，大差不差，都可以拆成工具。系统提示词里说：若用户要设定时，就用标签调用「设置定时任务」的工具；或者做一个按钮，点开之后往提示词里注入「目前在设置定时任务」。工具被调用后，本质是拉相关代码，往项目里植入一个简单脚本：隔多久干什么、发什么请求。很简单。所有智能体大概就这些。

一个智能体调用很多工具，是一套完整过程。最简单的定义：当模型不能再调用工具为止。它什么都会，很可能会想多。如何让它想少一点、快点完成？很多工具支持设置最大工具调用次数，Cursor 里就有。设成一次对话最多 200 次，然后动态注入：你现在只剩 197 次、160 次。模型就会自己分析，不能一直发散，要在更少的次数里完成。这也是一套优化。规定每次如何调用工具、如何拼接上下文，这一整套工程叫 harness engineering。Harness 是马具的意思。Codex 有自己的一套智能体调用流程，Claude 也有，所以 Codex 和 Claude Code 各有 harness。各家都在讲 harness，本质就是你怎么编排。

## ReAct 只是不断逼近

ReAct 框架其实也是一个最简单的智能体框架，和刚才说的差不多：工具不再调用时停止输出，用状态机查看模型目前什么状态。举个具体例子：你让它出一套微积分考研真题。第一步，Codex 分析意图，变成上下文——我要出题。知识库里没有考研真题，是不是得网络搜索？于是调用一次 tool=search。结果回来，再根据刚才所有内容分析：出题时有没有 Skills 可以用，再次调用工具。每一次执行都是先调用一次工具，尝试逼近答案，再继续逼近。这就是 ReAct。它目前几乎被吹成 Agent 架构的鼻祖。发明它的人大概也没想到会被吹成这样。本质很简单。

为什么要理解这些再跟别人说？你根本不需要知道代码怎么写，只要知道这些原理。AI 项目生成，本质就是提示词：规定提示词长什么样，不同模板就是拼接不一样的提示词，用一个东西去管理、注入、拼接。不用管代码是什么，但要跟 AI 描述这个场景。拼接完再调用生图模型，非常简单。若必须先搜索，就接入网络搜索工具，写在系统提示词里：生图前必须先调一次搜索。规定可以很多元。这个东西就是 harness。

若不跟 AI 说清楚，把用户的原始需求丢给 Codex，开一天目标模式，绝对会跑出一堆屎山。这就是为什么要了解这些。不了解，每一次都是黑盒，模型会想得非常多、非常复杂，大量时间花在用处不大的端测上。端测完全可以自己做，非常费 token。AI 启动项目、控制浏览器看功能好不好使，你自己测就很好。你专注的时候，完全可以给它布置下一个任务，效率才最大化。不一定所有事情都用 Codex 最好的模型，也可以用别的。而且 Codex 的 harness 很重。按我刚才的描述：做任务时它会强制先调一次工具，了解当前仓库状态，再了解最近改动，再分析需求，再搜索有没有好办法，明确之后才动手；做完先跑测试，改完再测，端测完再测，一直在测试，浪费时间和 token。有时候可以用更轻量的模型，在更轻量的 IDE 里做。专业人士的一个区别，就是可能用更少的 token 做更有价值的事，并且做得更好。

## 窗口会过，自己的需求还在

希望这些能对大家有帮助。我真心觉得大家很厉害。我算实习过的人，在很多真正的大厂里大家缺钱，其实没有那么好接单；现在有 AI，能凭自己的能力去接，最重要的是珍惜。珍惜之后，尽量尽到责任，项目能做好就做好，并且一定要在做项目的过程中学经验。学经验不只是为了更好接单——可能再过几个月就接不到了，价格更低，更卷。非专业人士可能无法交付更好的东西；专业人士可以在更短时间交付更好的东西，因为价格可能更低，他们有自己的模板。以后市场会很激烈，需求也会转向。

这次全国最大的黑客松，其中一个赛道是「节约精神」，要求顶尖选手三天内做出能让 AI 自主进化、研发产品的东西。说句不好听的，他们可能是在找用户有没有好 idea；有好的就给合作机会，不好的也可能借鉴思路，融进自己产品。再过几个月也许真的就有一款这样的产品。这次赞助商 Superion 我没用过，本质是类似的低代码平台：几句话做出满足客户需求的东西。通用类一旦做起来，很多老板会选择自己口喷生成软件；发现自己做不了、东西很复杂，才去请外包。那时遇到的问题一定是 AI 无法解决的，或非专业、不了解这些原理的人无法解决的。核心竞争力又没有了。这是第一点。

第二点，成都这个 AI 时代，很多时候本质是你自己有需求，发现大家也有，希望做一款产品帮到大家。这方面空缺非常大，竞争也非常激烈。我自己就在做这方面的创业，已经做了很多项目，虽然没怎么成功。更有价值的需求，不是生活里随手借鉴的，而是你对生活或某个领域有很深的理解；再就是对开发本身有很深的理解。我们目前做的一些产品其实也面向开发者，你需要对一些东西真正了解得很深。

希望大家不只是在这次闲鱼学到东西，也能有一些自身成长。再次感谢二组的组长，以及水猫，真的非常负责、用心。他可能把很多时间放在时间管理上，本质上会放弃一些学技术的机会。大家应该好好感谢一下。大概是这些。
