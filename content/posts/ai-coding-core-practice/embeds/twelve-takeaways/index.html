十二条最值得带走的结论

从「能跑起来」到「能长期上线维护」，中间的差距基本都写在这里。

  1. 01
    边界感敢不敢接长期大单，取决于是否清楚 AI 能力边界和上线后的影响面。
  2. 02
    耦合改一个 bug 冒出三个 bug，根源几乎都是模块该拆没拆。
  3. 03
    架构决策专业知识加大量实战经验，经验往往占大头。
  4. 04
    渐进优于冒进目标模式要建立在清晰的分块验收之上，否则容易陷入无限拆分。
  5. 05
    边界感（执行层）改一个字的任务，不需要重 harness 走完整流程。
  6. 06
    别切断学习通道把不懂的功能关掉看似省心，代价是失去继续成长的入口。
  7. 07
    求证习惯AI 的输出不是每个字都对，保留一份可以被推翻的怀疑。
  8. 08
    复用是本质组件库和 SDK 能把几万行代码压缩到几百行。
  9. 09
    MCP vs SkillsSkills 靠 description 按需调用，比 MCP 更省 token。
  10. 10
    没有 Git 就没有记忆锚点AI 依赖哈希对比历史代码，版本控制是它「记得住」的前提。
  11. 11
    生产环境不是开发环境数据隔离、并发、稳定性，是企业级项目最容易被低估的部分。
  12. 12
    Agent 不神秘本质是提示词加工具调用，看懂这层就能自己动手做一个。
