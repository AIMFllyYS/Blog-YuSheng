# 穷、安全感，以及我为什么改把时间押在 AI 开发

今天记了一下账，整个人要炸掉。我个人非常穷。要攒钱只能靠平常生活费，或者过年那些压岁钱，手里经常完全没钱。没钱意味着非常没有安全感，很多时候是真吃不上饭。饭都吃不上，住的地方不行，脾气能不暴躁才怪。心情一炸，就完全无法投进任何状态。

未来的方向，医学是一方面，剩下的时间我都打算弄 AI。以前我是摄影爱好者，压岁钱基本上都花进摄影和剪辑里了。开销比较大。

## 卖掉摄影家当

我把镜头、相机、入门全套组件加在一起算了一下：去年一年不到一万、将近一万。数量不小。钱是一点点攒的，剩下的都去搞摄影。我不玩游戏，衣服鞋子什么也不买。

当时攒出全套之后，本来还想多多参与社团。有大约一年的剪辑摄影经验，学校里任何一个社团的媒体部我都可以进，真的随便进。很低成本凑齐了能拍的东西：稳定器，各种焦段的镜头。镜头不一定贵、不一定质量很好，但学校所有活动都可以拍。这是一件很好的事。

后来我想清楚了：要认真搞 AI。学校里加了很多社团和学生组织，破事一堆。我在逐渐退社团、退学生组织。意义不是很大。评奖评优也轮不到我——说句不好听的，我很胖，体测过不了，过不了就评不了奖。我是强基，不用保研，也不需要学生干部经历去抬比例。若说学生干部对就业有帮助，简历上这些履历还不如我举办一些 AI 活动。奖励没有任何意义，纯浪费时间。

既然要退，一方面退完之后确实没有摄影需求；另一方面，以前剪辑摄影也能赚一点，一个片子大概五六百，但很累，没有用 AI 交付产品爽。剪辑接不到单，AI 也接不到单，还不如去弄 AI。

说来也无语，一万多的东西，目前能卖到四千多就不错了。相机镜头配件本来没那么容易降价，但我很着急出，没有时间和买家磨。打算打包出；单出应该能卖到五千甚至六千，要花大量时间，我不打算再投入了。

## 功能层，不是纯前端

账算完穷得一批，又想到工具利用率。我做 AI 网站。真要接单，我不太擅长纯前端类，团队单也很烧 token：前端要做好，需要很强的模型，审美和打磨能力都要强，烧的钱很多。我认为没太多必要，我也不太愿意花时间打磨一个很好看的前端。我做的更多是功能层。实用类网站和纯前端站不一样，它要的是对专业知识的经验——实战经验、开发经验。经验是用来指导 AI 的。AI 编码能力很强，我不是计算机专业，它也可以写出来。

经验不是教科书上那些。教科书上的东西，AI 可以写成代码：TypeScript 怎么用、Python 怎么用，写在相关书里。软件工程、算法原理、操作系统，很多是思维和方法论。软件工程我发现非常像组织管理，比如各小组怎么排工期、怎么分配任务。很高的维度上，方法论是相通的。它对专业知识要求不是那么高。组织 AI 怎么干活，并不太需要把专业啃透，需要的是开发经验、指挥 AI 的经验，以及明白 AI 的边界。前期交付的大部分单子，对专业知识的广度浅尝辄止，就可以做出来。

## 半天把角色做完，上课时跑目标模式

目前我觉得比较好的方法：用大概半天派活。工具上，GitHub 大家都知道，开源仓库。Git 做分支，GitHub 管仓库，还有一个非常好的功能是 Issue 驱动开发。一个项目可以提很多 Issue，不只是记问题，也可以补「项目未来要干什么」、P0 / P1 / P2 阶段要干什么，相当于排工期。分支管理对外对内都比较友好，代码留存也好：就算 AI 不小心把代码删了，云端还在。本地有 Git，代码在项目目录的 `.git` 里，AI 一般不会删这个；万一连盘都删了，云端也还有。

用户给到一个模糊需求，第一件事是当产品经理，把它翻译成工程化的、AI 可执行可看懂的、边界清晰的需求。第二是当设计师，把功能先变成设计稿。Pencil、Figma 都是绘图工具，Google Stitch 也可以。剩下两三个小时讨论架构：简单应用也需要最基础的架构决策，决策可以来自开发经验。我这方面专业知识不高，做简单产品肯定没问题。大家现在提到的单，价格在一万以内，基本都是简单单，靠 AI、力大砖飞可以。一万以上很复杂的单，不是跟 AI 口喷就能做到的：代码量非常大，上下文有限，架构决策做不好、规范不统一、模块拆不开，模型会发现我知道怎么修，但上下文不够，修不了。

马上开学，开发模式要变。大概：一个小时确定需求边界，一个小时画设计图，很多 AI 都支持。你不用说得很专业。一个通俗道理：你用十句话描述一件事，和两句专业术语，在 AI 的高维视角里语义可以约等于。它会把你不标准的语言翻译成给自己看的工程术语。小型开发，这样足够。

然后写架构文档、规范。最经典的一条：不要堆长代码。写 HTML，和用架构写大型项目，是两回事。大型项目动辄十多万行，塞在一个 HTML 里，AI 不好改，很难定位行数；上下文不够；塞过量它也无法分析，函数套函数，非常混乱。聪明的人把一个 HTML 拆成十个文件，每个文件行数很少，文件名就是这块功能。更规范的架构还会规定数据放哪、注册放哪、路由放哪。拆开，AI 能看懂。很多时候平均行数在 200 到 300，一个模块一份代码，一个小组件一份代码。要高复用：做一个复杂的 SaaS，像飞书那样每个页面都有通知栏，不必每个页面写一遍，写一个通知栏，别处引用即可。模块要拆分，职责要清晰，要低耦合。

规范定完再排工期。假如只做一个飞书文档单品：文件导入、协作、把 Markdown 渲染出来，编辑、保存、增删改查；不同板块——代码块、引用块、图片——怎么渲染。前面这些最重要的基础放进 P0，一共五六个功能，再拆成二三十个子任务，每个任务让 AI 提前决策好。P1 再放图片、音视频、代码块、可视化、画布，也拆成大约二十个任务。P3 再把画布里那些绘图功能拆成三四十个。一个需求就变成大约一百个可执行任务。不想用 GitHub，也可以按顺序写一百个计划文档；或者用 GitHub Issue。这一步还没改代码，但 AI 能看出顺序有没有问题、模块之间有没有关联。你不可能在画布还是 P2、还没做出来的时候，就去开发画布里的功能。先有画布，才能在它上面加东西。

一百个任务清楚之后，就开 Codex 的目标模式，用一般的模型就行。现在的模型做到了更低成本、更高智能。Grok，或者 GPT-5.6 配 Codex，都可以跑目标模式：按顺序推进 Issue。每一个 Issue，先了解现在做到第几个、当前任务是什么，再做，做完审查代码、端测一下，没问题就下一个。很清晰。周日把需求拆好，周一上课，AI 在做；回来验收，作业写完，第二天再去上课，AI 继续做。一个周日的需求，周三周四就可能做完，再验收改 bug。这样可以按周、按课时，快速做很多项目。

```mermaid
flowchart LR
  A[需求边界] --> B[设计稿]
  B --> C[架构规范]
  C --> D[拆成 Issue]
  D --> E[上课时跑目标模式]
```

所有角色放在最前面，本身就清晰，也给我省下很多时间。多的时间干什么？上课。我毕竟是个学生，也不能逃课。

## 订阅怎么拆，九月的账

若开目标模式跑十个小时，GPT 那档 20 美元也扛不住。Grok 就不一样，真的很便宜。这波涨价完之后，Grok 是最便宜的，效果还强。

订阅也有讲究。

Claude 必须订。它最适合深度架构决策，能力最强；也适合人生决策——反思、学业困惑、人生困惑，林子哥讲的东西要不要分析，都可以跟它聊，情商高；写作业类任务也可以交给它。订一个 Pro 就够了，我大概只干这些事。

第二，GPT / Codex 确实很合算。Grok 拿来执行，分析仍可以交给更强的模型。

第三，订 Kimi，是因为我自己跑的 OpenClaw（小龙虾）走 Kimi 的云服务。部分长任务可以交给 Kimi。养虾用套餐里的 2.7 其实蛮够，毕竟多模态，额度还可以。

再是 OpenRouter，很便宜，5 美元、60 美元我觉得很合算。轻量任务，或类似目标模式，可以把部分额度接到 Codex 里用。

Google 的 Ultra 可以家庭组共享，价格从原来两百多美元降到两百多人民币。好处是：Google 系列绝对是所有模型里最懒的一个，但做数学相对很强，速度很快；网页端比较适合学习；NotebookLM 特别适合我复习——在我没有开发自己的学习项目之前，学习还是打算用它。Veo 3 可以生成视频，就不用开即梦会员了。Google 当 IDE 来编程，Gemini 的副驾驶能力还是很强；Stitch 做设计也很强。

下一个赶上活动，99 美元一个月，很合算。一头像云端的大号小龙虾，能连一台云电脑。没有苹果手机，有的话更爽。我是医学生，常有数据统计、调研，适合丢给云端——用 Kimi 的 OpenClaw 拴在自己电脑上，得保证电脑一直开着，不一定方便。最近很多远程软件限制更高，要开会员才能边用，梯子也很排斥。另一头是 Heavy 系列，网页端及时查找信息最强。之前把一些总结封装成 PDF，我用 Claude 做前端设计、收成 Skill 再丢进去，效果非常好。生图生视频绑在额度池里，量其实不少，学校课程要做视频也能用上。它还会送 Cursor Ultra，原价 200 美元，很合算；大约 2000 刀的额度池，比较适合刚才说的 Issue 驱动。每月大概还有 500 刀 API，任意模型，包括 Claude。我还比较习惯用 Cursor IDE：下面终端就能用 Claude Code，左侧插件接 Codex，一个页面里两套都在，做开发真的超级方便。更专业的开发肯定要有 IDE，而且它和 Codex 对得上。

这样算下来，必要支出大约 1300。我已经算比较省了。吃饭 1500，还是比较贵，要省钱的话饮食上还得再省。每个月必须接单超过 1000 元。一个月接一个单其实难度比较大，主要是接不到；能接的话，只要超过 1000 就可以，至少能做到正支出。摄影设备卖掉，不用担心现金流断裂。之前还有一些竞赛和其它东西，加在一起一千多。粗算九月应该能有七千差不多。今天漏了：机器人每个月大约 100 还没算。卫生纸、洗衣液这些消耗品，开销其实会比想象大。目前是粗算，还要精算。预算还是比较重要的。

如果大家愿意听或看，希望也能有所收获。不开发一个纯前端应用，而开发一个真有功能的应用——比如以前那种小程序商城——更好的开发流程大概就是这样，可以参考。
