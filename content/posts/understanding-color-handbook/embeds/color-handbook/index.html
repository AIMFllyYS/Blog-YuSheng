为什么"差不多"的两个颜色
放在一起会难受
颜色从来不是孤立存在的——它只在"和别的颜色的关系"里成立。看懂这本手册，就是学会看懂关系。

先从一个真实的翻车现场说起。

有一个 Android 应用，设计师想做"苹果式纯净风"：背景用玉白色，卡片用很浅的灰，图标用清透的浅蓝，主文字黑色、备注文字灰色——每一个单拿出来都很"正常"，都是大厂规范里出现过的颜色。但真机上看起来完全不是那么回事：

  • 备注文字几乎看不清。灰色备注叠在浅灰卡片上，像用淡墨写在毛边纸上，要多看一眼才能辨认。
  • 卡片看起来"脏"。明明是精心选的浅灰，在屏幕上却泛着一种说不清的粉肉色，和玉白背景之间有一种廉价的错位感。
  • 蓝色图标格外刺眼。浅蓝图标压在暖调灰卡上，冷和暖互相打架，看久了眼睛累。

问题出在哪？出在"关系"，而不是"单个颜色"。这个界面的每一个颜色单看都不算错，但它们之间的三组关系全错了：亮度关系（备注灰和卡片底的亮度差太小）、色温关系（冷蓝图标和暖灰卡片互相排斥）、层级关系（卡片和背景几乎分不出谁是谁）。

你在生活里很少"单看"一种颜色，你看到的永远是颜色的组合。组合里的规则，就是这本手册的全部内容。—— 全册主线

这本手册会带你从最底层走起：先搞清楚屏幕是怎么"造"出颜色的（第 1 章），再学会用语言精确描述一个颜色（第 2 章），然后学搭配的经典公式（第 3 章）、UI 行业的硬规则（第 4 章）、苹果谷歌这些顶级系统是怎么做的（第 5 章）。之后我们走出屏幕，看看摄影、电影和 AI 视频里的冷暖配色（第 6 章）。最后，带着全部装备回到开头这个翻车现场，把它的配色问题一条条拆开、量化、修复（第 7 章）。

每一章的讲法都一样：先用大白话把道理讲透，再用"行话怎么说"的术语框告诉你专业名词——读完你既懂了原理，也学会了和设计师、工程师对话的语言。

行话怎么说 · 先认识三个全册高频词 色相（Hue）：颜色是"什么色"——红还是蓝。饱和度（Saturation）：颜色有多"鲜"——艳还是灰。明度（Lightness / Value）：颜色有多"亮"——浅还是深。任何一个颜色都能用这三个数定位，第 2 章会把它讲成肌肉记忆。

CHAPTER 01 · 显示基础
01
屏幕里的颜色：
色域与显示基础
屏幕上的颜色不是"涂"上去的，是"灯"点出来的——理解这一点，你才能理解为什么同一张图在不同设备上颜色不同。

1.1 颜色是光的"剩饭"

先建立一个最底层的认知：颜色不是物体自带的属性。阳光（白光）其实是一桌"自助餐"，里面什么波段都有；一个红苹果之所以红，是因为它把绿、蓝波段的光"吃掉"（吸收）了，只把红波段"剩下"（反射）给你。你看到的颜色，是光被物体挑挑拣拣之后的"剩饭"。

这也解释了一个常见现象：同一件衣服，在商场的暖光灯下和家里的白光灯下颜色不一样。衣服没变，是"自助餐"的菜单变了。科学家管这种现象叫同色异谱——两种光谱成分完全不同的光，看起来颜色一样。

人眼能接管的波段大约只有 380–780 纳米，这叫可见光谱。你眼睛里有三种视锥细胞，分别对长波（红）、中波（绿）、短波（蓝）敏感——全世界所有关于颜色的工程标准，都建立在这"三个传感器"之上。

行话怎么说 可见光谱（Visible Spectrum）：约 380–780nm。视锥细胞（Cone Cells）：L/M/S 三种，分别感红、绿、蓝。同色异谱（Metamerism）：光谱不同、观感相同。"衣服在店里和家里不一样色"就是它。

1.2 加色与减色：开灯 vs 盖滤镜

世界上有两种"造颜色"的方式，逻辑正好相反：

屏幕是"黑屋子里开灯"（加色）。每个像素里有红、绿、蓝三盏小灯，越开越亮，三盏全开就是白色。这叫加色模型 RGB——红绿蓝光越加越亮。

印刷是"白纸上盖滤镜"（减色）。白纸本来反射所有光；青、品红、黄三色油墨各自"吃掉"一部分光，叠得越多越暗。理论上三色全叠应该是黑色，但现实中的油墨不纯，只能得到一坨浑浊的深棕——所以印刷必须再加一个真正的黑版 K，凑成 CMYK。这叫减色模型。

行话怎么说 加色模型（Additive Color Model, RGB）：光的三原色红绿蓝，全亮为白。减色模型（Subtractive Color Model, CMYK）：油墨三原色青品红黄 + 黑版（Key）。K = Key Plate，取末字母避免和蓝（Blue）混淆。

这直接回答了"为什么印刷品总比屏幕暗、没屏幕艳"：屏幕是自发光，亮度自己说了算（典型 200–1000+ nit）；印刷品只是"环境光的搬运工"，最亮也只能亮过那张白纸。而且 CMYK 油墨能调出的颜色范围比屏幕小——屏幕上那种电光蓝、荧光橙，油墨根本印不出来。所以同一个品牌蓝，屏幕值和印刷值必须分开管理（第 6 章细讲）。

1.3 色域：你的屏幕有一盒多大的蜡笔

先纠正一个流传很广的说法："差的显示器是 RGB，好一点是 sRGB，更全是 Adobe RGB。"——这句话把概念搞混了。RGB 不是一档色域，而是"用红绿蓝三盏灯混色"这套方法本身；sRGB、Adobe RGB、DCI-P3、Rec.2020 全都是这套方法下面的具体"颜色全集"。真正区分显示器高低的词叫色域。

色域就是一台设备能调出的颜色全集，像一盒蜡笔：sRGB 是 12 色基础装，DCI-P3 是 16 色学生装，Adobe RGB 是专为画风景配的 20 色装（青绿色多），Rec.2020 是 48 色豪华装，ProPhoto RGB 则是连你眼睛都看不见的颜色都塞进去的仓库装。

图 1.1 — CIE 1931 色度图（马蹄图）示意：马蹄内是人眼能见的所有颜色；任何三色显示器只能盖住一个三角形，三角形越大色域越广（示意图，非精确坐标）。

这张"马蹄图"是 1931 年国际照明委员会把人眼能见的所有颜色画成的一张地图。读法很简单：越靠边缘越鲜艳，越靠中心越接近白；底部那条直边是自然界不存在的"紫线"（红蓝混合的品红系）。任何显示器的红绿蓝三盏灯，在图上只能连出一个三角形——所以没有任何三色显示器能显示你眼睛能看到的全部颜色，这是物理决定的，不是技术不行。

行话怎么说 色域（Color Gamut）：设备能表现的颜色范围。色彩空间（Color Space）：一套具体的颜色定义（原色点 + 白点 + 伽马）。CIE 1931 色度图（Chromaticity Diagram）：人眼可见色的"世界地图"。Display P3：苹果版 P3——P3 的原色 + D65 白点 + sRGB 曲线，iPhone 7 起全线采用。

1.4 色深、Gamma 与白点：三个"看不见但天天影响你"的参数

色深：从黑到白切多少刀

色深决定每种原色能分多少级。8bit 每通道 256 级，三通道组合出约 1677 万色；10bit 每通道 1024 级，约 10.7 亿色。级数不够时，天空、日落这类平滑渐变会被切成一道道"台阶"，这叫色带。口诀：色域越大越需要高位深——ProPhoto RGB 用 8bit 必然色带，必须 16bit。廉价面板的"8 抖 10"（8bit+FRC）是靠快速闪烁骗眼睛，仔细看有噪点。

Gamma：暗部优先的"存储策略"

人眼对暗处变化敏感、对亮处迟钝。所以存图时刻意把暗部提亮存，屏幕显示时再按一条幂曲线（约 2.2）压回去——一存一放刚好还原，还把有限的位数优先分给了暗部。这套机制源于 CRT 时代的物理特性，今天的 LCD/OLED 是主动模拟它以保持兼容。sRGB 实际用的是一条分段曲线（暗部直线 + 2.4 次幂），整体等效 ≈2.2。

白点与色温："白"到底多暖多冷

"白"不是绝对的。屏幕行业约定俗成的标准白是 D65（约 6500K），模拟正午日光；印刷看样用更暖的 D50（约 5000K）。色温越低越暖黄、越高越冷蓝——很多手机出厂默认 7000–9000K 的"冷屏"，看着通透其实偏蓝刺眼；"护眼模式"本质就是降色温。

行话怎么说 色深 / 位深（Bit Depth）；色带（Banding）：渐变的台阶断层。Gamma 校正（Gamma Encoding）：按幂曲线编解码亮度。白点（White Point）与相关色温（CCT，单位 K）；D65 / D50：屏幕与印刷的两个标准光源。

1.5 色彩管理：为什么同一张图换个设备就变脸

每台相机、屏幕、打印机"说颜色的方言"都不一样。ICC profile 就是每台设备的"方言翻译表"：文件先被翻译成一种与设备无关的"国际清算货币"（CIELAB/XYZ），再翻译成目标设备的方言。同图不同色通常有三个原因：设备色域不同（超出的颜色被硬切或压缩）、文件内嵌的 profile 被忽略（老 App 一律当 sRGB 解析，广色域照片直接变灰变淡）、设备没校准（出厂偏色或老化）。专业显示器的"出厂校色报告"里那个 ΔE（色差）数值，ΔE<2 才算专业可用。

1.6 OLED 与 LCD：黑得下去 vs 亮得均匀

LCD 像"永远关不干净的百叶窗 + 常亮大灯"：背光一直在，黑色是液晶努力挡光的结果，所以黑得发灰，对比度约 1000:1。OLED 每个像素自己发光，显示黑色时直接断电——黑位接近 0 nit，对比度理论无限大，侧看颜色也更稳，旗舰普遍覆盖 100% DCI-P3。代价是烧屏风险、低亮度常用 PWM 调光。开篇那个"卡片泛粉肉色"的观感，就常发生在 OLED 屏上——近白浅灰在不同面板、不同亮度下的实际呈色会有轻微漂移。

1.7 手机广色域：App 得"举手申请"

2017 年（Android 8.0）之后，好手机的屏幕都能显示比 sRGB 更艳的颜色，但 Android 的逻辑是"怕翻译出错，默认只许说普通话"：App 想用广色域，必须在代码里声明 colorMode="wideColorGamut"；照片 App 解码 P3 图片时还要保留色彩空间信息，否则系统按 sRGB 处理，P3 照片在未适配的 App 里会明显发灰发暗。iOS 则是系统级自动转换，开发者基本无感。另外，手机"鲜艳/自适应"显示模式普遍过饱和，"自然/原彩"模式才是准的——同一张图在不同手机上颜色不同，常常不是面板差异，而是显示模式差异。

行话怎么说 ICC 特性文件（ICC Profile，ISO 15076-1）；ΔE（Delta E）：色差数值。广色域（Wide Color Gamut, WCG）；Android API：isScreenWideColorGamut()、COLOR_MODE_WIDE_COLOR_GAMUT。

CHAPTER 02 · 颜色模型
02
描述颜色的语言：
色相、饱和度、明度与颜色模型
任何一个颜色，都能用三个数精确定位：它是什么色、有多鲜、有多亮。学会这套语言，"好看一点"就变成了可执行的指令。

2.1 色彩三属性：一杯果汁的比喻

把颜色想成一杯果汁：色相是"什么水果"（橙汁还是蓝莓汁），饱和度是"兑了多少水"（越兑越淡、越接近白开水的灰），明度是"在多亮的灯下看它"（从漆黑到刺眼）。这三个维度互相独立——可以有"很艳的暗蓝"，也可以有"灰扑扑的浅色"。

色相在色轮上用角度表示：0°=红、60°=黄、120°=绿、180°=青、240°=蓝、300°=品红，转一圈 360° 回到红。记住这六个锚点，以后看到 HSL 数值就能心算出色相。

行话怎么说 · 三属性在不同体系里的名字 色相 Hue 各处同名。饱和度 Saturation（HSL/HSV 用语，"相对"纯度）vs 彩度 Chroma（孟塞尔/OKLCH 用语，"绝对"鲜艳度）。明度：孟塞尔叫 Value（0–10），HSL 叫 Lightness（0–100%），HSV/HSB 叫 Value/Brightness，CIELAB 叫 L*（0–100）——名字像，公式各不相同。

2.2 最容易混的四组词

易混词区别一句话
色温 vs 色调色温是光源的物理参数（单位 K，可测量）；色调是画面整体的色彩倾向（主观感受）。
饱和度 vs 明度饱和度管浓淡（离灰多远），明度管明暗（离黑白多近）。
灰度 vs 灰阶灰度是"只有明暗没有颜色"的图像模式；灰阶是黑到白的楼梯级数（8bit = 256 级）。
色彩 vs 颜色基本同义："颜色"是口语词，"色彩"偏学术与艺术语境（色彩学、色彩管理）。

2.3 浓淡三兄弟：Tint、Shade、Tone

调色时有三种"稀释"纯色的方式，名字必须分清：Tint（加白）——粉红是红的 tint，明度升、饱和降；Shade（加黑）——藏青是蓝的 shade，明度降；Tone（加灰）——米色、肤色大多是 tone，饱和降、明度大致不变。设计系统里一整套"50 到 900"的品牌色阶，本质就是 tint 与 shade 的梯度。

行话怎么说 Tint / Shade / Tone：纯色 + 白 / + 黑 / + 灰。注意英文 tone 一词多义：颜料语境是"加灰"，摄影语境是"影调/明暗层次"，中文都常译"色调"，看上下文分辨。

2.4 RGB 与 HEX：颜色的"门牌号"

屏幕上的每个颜色都是红绿蓝三盏小灯各自的亮度值（0–255）。HEX 码只是把这三个数用十六进制缩写成一个"快递单号"：#RRGGBB，两两一组。换算口诀：两位十六进制 XY = X×16 + Y（A=10 … F=15）。所以 #FF0000 是纯红、#808080 是中灰；#3B82F6 = rgb(59,130,246)，一种常见的蓝。每位成双时可简写成 3 位（#F00）；8 位写法 #RRGGBBAA 末尾两位是透明度。HEX 和 rgb() 完全等价，只是进制不同，且默认锚定 sRGB。

2.5 HSL 与 HSV：像说话一样选颜色

RGB 的问题是"不像人话"——你能脱口而出 rgb(87,121,203) 是什么色吗？HSL 和 HSV 把颜色重新装进"色轮 + 明暗轴"的立体模型里，让"来个深一点的蓝"成为一步操作。两者的色相 H 完全一致，区别全在中间那条明暗轴：

HSL · 双圆锥

黑 — 纯色 — 白 三点共线

L = 0% 一定是黑，L = 100% 一定是白，L = 50% + S = 100% 才是最纯的颜色。CSS 爱用它：做"变亮一点/变暗一点"的派生色（hover 态、色阶梯度）只需动 L 一个数。
HSV / HSB · 单圆锥

顶点朝下是黑，顶面边缘最纯

V = 100% + S = 100% 才是最纯的颜色；要白必须 S = 0。Photoshop 等设计软件爱用它：横轴加白、纵轴加黑，符合画家调颜料的直觉。
行话怎么说 HSL（Hue, Saturation, Lightness）；HSV / HSB（Hue, Saturation, Value / Brightness——两者完全相同，只是改名）。换算关系：HSV 的 V = max(R,G,B)；HSL 的 L = (max + min) / 2。记忆锚点：同一个 hsl(74,100%,50%) = hsv(74,100%,100%)。

2.6 一条三代进化线：HSL → CIELAB → OKLCH

HSL 有一个隐蔽的硬伤：它对"亮度"的定义不照顾人眼。

HSL 的 L 是 RGB 通道的几何中点，完全不考虑人眼对绿光最敏感、对蓝光最不敏感。于是 hsl(60,100%,50%)（纯黄）和 hsl(240,100%,50%)（纯蓝）数值上 L 都是 50%，看起来黄却亮得多。后果很实际：同 L 值的跨色相配色"看着不齐"，做色阶梯度时忽深忽浅，渐变中间还容易发脏。

L = 50%
纯黄 hsl(60,100%,50%) · 看着很亮
L = 50%
纯蓝 hsl(240,100%,50%) · 看着很暗

第二代 CIELAB（1976）就是来解决这件事的：它按"人眼看起来差多少"重新编号，数值差多少、眼睛看到的差别就（大约）是多少——这叫感知均匀。它的三根轴：L* 只管明暗（0 纯黑到 100 纯白），a* 是绿↔红对立轴，b* 是蓝↔黄对立轴。它的极坐标形式 LCH（明度 + 彩度 + 色相角）对设计师更友好。两色之间的"距离"叫 ΔE（色差）：ΔE<1 基本不可辨，1–2.3 是"恰可察觉"，>5 一眼即知。但 CIELAB 在高饱和区（尤其蓝色）仍不够均匀，转换也笨重。

第三代 OKLCH（2020，Björn Ottosson 提出）是"又准又好用"的修正版：L 真正等于"眼睛觉得的亮度"——同 L 的不同色相看起来真的同样亮；改色相、改彩度都不会偷偷改变明暗。于是设计系统的 50–950 色阶可以"每档看起来差的量一样"地机械生成，渐变不再穿过脏中间色，深浅色模式和 hover 态都能用"加减 L"推导。Tailwind CSS v4（2025）已把默认调色板整体迁到 OKLCH，主流浏览器 2022–2023 年起全部支持，它正在变成设计系统的事实标准。

行话怎么说 感知均匀（Perceptually Uniform）：数值距离 ≈ 视觉差异。CIELAB / L*a*b*（1976）与其极坐标形式 LCH。ΔE（Delta E）：色差。Oklab / OKLCH（2020）：新一代感知均匀空间，CSS 写法 oklch(0.7 0.15 150)。

2.7 孟塞尔：一百多年前的"颜色公寓楼"

这条进化线的祖师爷是 1905 年美术教师孟塞尔建立的系统——史上第一个把颜色拆成三个"感知等距"维度的体系：H 色相（红黄绿蓝紫 5 主色 + 5 间色，共 100 级色环）、V 明度（0 纯黑到 10 纯白共 11 级等距灰）、C 彩度（从中性轴向外辐射，越往外越艳）。标注法 H V/C，比如 5R 4/14 = 正红、明度 4、彩度 14，大致是朱红。它像一座公寓楼：楼层是明度、门朝向是色相、离电梯的距离是彩度。楼不是规整的圆柱——纯黄在高明度处最艳、纯蓝在低明度处最艳，所以楼体歪歪扭扭——这正是"感知优先于几何"的证据。至今 USDA 还用它给土壤颜色定级。

2.8 对比度的数学：把"清不清楚"变成一道算术题

"字和背景差不差"其实可以精确计算，无障碍标准 WCAG 就是这么定义的，一共四步：

  1. 把 R、G、B 各通道从 0–255 归一化到 0–1。
  2. 逐通道线性化（去掉 Gamma）：小于等于 0.03928 的直接除以 12.92；否则算 ((c+0.055)/1.055)^2.4。
  3. 算相对亮度：L = 0.2126×R + 0.7152×G + 0.0722×B。三个系数就是人眼敏感度——对绿最敏感、对蓝最不敏感（纯绿 L≈0.72，纯蓝 L≈0.07，这就是"黑底纯蓝字只有约 2.4:1、必然不及格"的原因）。
  4. 算对比度：(L亮 + 0.05) / (L暗 + 0.05)。量表从 1:1（两色相同，完全读不出）到 21:1（纯白 vs 纯黑，理论最大值）。

注意一个反直觉点：这套公式只看亮度差、不看色相差。蓝底橙字"看着撞色"，如果亮度接近，比值照样不及格——"刺眼"和"清楚"是两回事，前者是饱和度冲突，后者是亮度差。第 7 章的实战诊断会用它给真实界面"称体重"。

行话怎么说 相对亮度（Relative Luminance）；对比度比值（Contrast Ratio）；线性化 / 伽马展开（Linearization）。达标线先记两个：正文 AA 级 4.5:1、AAA 级 7:1（第 4 章给完整表）。

2.9 眼睛会骗人：三个必须知道的视觉错觉

同时对比：同一块中灰，放白底上显深、放黑底上显浅；放红底上微微泛绿、放蓝底上微微泛黄——颜色总被推向周围色的补色方向。开篇那个"灰卡泛粉肉色"的观感，一半功劳要记在它头上。马赫带：明暗交界处，亮侧会出现一条"更亮的亮边"、暗侧一条"更暗的暗边"——像素里根本不存在，是视觉系统在边界处的"锐化过冲"。色彩恒常性：白纸在暖黄灯下和蓝天下你都觉得是白的——大脑自动"扣除光源色"，和相机的白平衡是同一个思路；线索不足时它就翻车，2015 年刷屏的"蓝黑裙/白金裙"就是著名事故现场。三者的共同启示：视觉系统测的从来不是绝对光量，而是相对差异——所以设计里永远要在真实上下文中评估颜色，而不是盯着拾色器。

行话怎么说 同时对比（Simultaneous Contrast），1839 年 Chevreul 系统记录；马赫带（Mach Bands）；色彩恒常性（Color Constancy）。底层机制：视网膜侧抑制（Lateral Inhibition）与对立过程理论（Opponent-Process Theory）——视觉按红-绿、蓝-黄、明-暗三对对立通道处理信号。

2.10 色阶与曲线：照片明暗的两把扳手

直方图是照片的"明暗体检报告"：横轴亮度 0–255、纵轴像素数量。山峰偏左 = 曝光不足，偏右 = 过曝，全挤在中间 = 画面灰蒙蒙（该黑不黑、该白不白）。色阶（Levels）三个滑块：黑场右移 ="比它暗的全部判纯黑"、白场左移 = "比它亮的全部判纯白"、灰场滑块只拨中间调；两端一起内收就是"除霾增通透"。曲线（Curves）更精细：X 轴原亮度、Y 轴新亮度，S 形曲线（抬高光、压阴影）= 加对比度，是"通透感"的第一扳手；切到单个 R/G/B 通道调曲线就是调颜色——蓝通道右下压 = 加黄减蓝，金秋色调就这么来的。这组工具会在第 6 章的影视调色里再次出现。

3.1 为什么有三套"三原色"

"原色"就是没法用别的颜色调出来、但能调出其他所有颜色的底料。之所以有三套，是因为混色的媒介不同：

美术课教的红黄蓝（RYB）其实是历史经验模型；生理学上最准的是 RGB——你眼睛里就只有感红、感绿、感蓝三种视锥细胞；工艺上最准的是 CMY——青、品红、黄分别精确吸收红、绿、蓝光，混色最干净，所以专业印刷用它。三套体系之间有个漂亮的对称：RGB 两两相加点出 CMY，CMY 两两相叠印出 RGB。

原色两两混合得到间色（橙、绿、紫），原色再和相邻间色混合得到复色（红橙、黄绿、蓝紫……），1 套原色 + 3 间色 + 6 复色就组成了经典的 12 色轮——接下来所有配色公式，都是在这个轮子上画几何图形。

行话怎么说 原色（Primary Colors）、间色（Secondary Colors）、复色（Tertiary Colors）；色轮（Color Wheel）；RYB / RGB / CMYK 三套原色体系。

3.2 补色：最锋利的刀，用不好先割自己

色轮上正对门（相差 180°）的两个颜色互为补色：红–绿、蓝–橙、黄–紫。它们放一起对比最强、互相把对方衬得更艳——这是礼物；但如果两块面积一样大、又同样鲜艳同样亮，眼睛的"红-绿""蓝-黄"两对拮抗通道会互相打架，边界看起来发抖、闪烁，看几秒就累——这叫视觉振动，是"刺眼"的主要来源。

补色的正确用法三条纪律：① 一大一小——一色当主背景，补色只做小面积点缀；② 拉开差距——拉开明度差或降低一方饱和度，振动立刻消失；③ 别拿补色写正文——补色文字叠补色背景是阅读灾难，而且对约 8% 的红绿色盲男性来说那是一团同样的棕色（第 4 章细讲）。还要记住第 2 章的结论："看起来很跳"≠对比度合格——高饱和蓝橙的明度可能几乎相等，过不了 WCAG。

行话怎么说 补色（Complementary Colors）；视觉振动（Visual Vibration）；对立过程理论（Opponent-Process Theory）：视觉按红-绿 / 蓝-黄 / 明-暗三对对立通道处理信号——补色刺眼的生理学根源。

3.4 冷暖色调：不要钱的立体感

红橙黄让人想到火和太阳，叫暖色；蓝绿紫让人想到水、天空和阴影，叫冷色；绿和紫是中间地带（偏黄则暖、偏蓝则冷）。冷暖有一个超实用的空间属性：暖色看起来往前扑，冷色看起来往后退——不用任何阴影，就能在平面里做出前后层次。冷灰蓝界面 + 一个暖橙色按钮，按钮仿佛"浮"在界面之上，这是 UI 里最常用的免费立体感。风景画把远山画得更蓝更灰（大气透视），用的是同一条规律。

两个进阶要点：冷暖是相对的——同一个橙，在紫旁边显暖，在更红的橙旁边显冷；混合冷暖比全暖全冷更"有空气感"，做法是确立一个温度主导、再用相反温度小面积点缀。这条规律是第 6 章"橙青对比"的电影语言的地基。

行话怎么说 暖色 / 冷色（Warm / Cool Colors）；前进与后退（Advancing / Receding）；大气透视（Atmospheric Perspective）：物体越远越偏蓝、饱和度越低、对比越弱。

4.1 大师的色彩六规则（UI/UX 大师课 · 原文精要）

以下六条来自一位世界级 UI/UX 设计师的课程讲义，"来自多年经验，我会很严"是他的原话。注意它们和前三章的知识完全咬合——你会不断看到老熟人。

规则 01

避开刺眼的颜色

任何情况下都不要让刺眼的颜色进来。你唯一被允许用的是成熟的颜色——沉稳，不扎眼。过曝的绿、刺眼的浅蓝、喊叫的红，看几秒眼睛就累。哪怕只是页面上一个很小的元素，也不许用。"没有借口，没有通融。"
loud colors → mature colors
规则 02

探索色谱

你决定用蓝——世界上有数不清的蓝，同一种颜色的不同版本说着完全不同的语言。把整条色谱走到底再定夺。工具很简单：去搜 "brown color palette" 这类色板找启发，颜色代码没有版权。
explore the spectrum · color palette
规则 03

限制数量

限制，在设计里常常是好事。项目里的主色（强调色）最多两到三种。很多有经验的设计师会争，但这是多年经验换来的。他的教育品牌就靠"深蓝 + 白"两种强调色运转——简单到不能再简单，却是一套很好的组合。
accent colors ≤ 2–3
规则 04

保持一致

把色板调到所有视觉上去：按钮同类同色、与品牌主标志呼应；插画也选色板里那一档（如 unDraw 可一键换色）。同一种颜色在所有画面里扮演同一个角色——一致性本身就是设计工具，它抬高简洁，也抬高清晰。
consistency
规则 05

对比平衡

要用对比，不要色彩爆炸。好对比：浅红底上压一块更饱和的红——同色系但差得够远。坏对比：字难读、看着费劲。认真把不同颜色叠在一起试，把对比做平衡是颜色上非常要紧的规则。
contrast, not color explosion
规则 06

感受你的颜色

你自己必须先感受到你的设计，因为最终用户多半会感到同样的东西。对着色板问自己：换作你，会点吗？会买吗？会信任吗？还是会离开？坐在那里，看你的选择。
feel your colors

4.2 大师课的另一条颜色规则：颜色是"可理解性"的工具

大师课在讲"可理解性"时给颜色补了一条定位：对比在可理解性上非常有用——相当暗的底，相当亮的字，两者都是成熟的颜色，你不会看累；同时因为对比，它们可理解。前景色和背景色差得够远，你能轻松读完，也不会读错。这把第 2 章的对比度数学和本章规则 05 缝在了一起：颜色不是装饰，是让用户"读得懂"的功能件。

WCAG（Web 内容无障碍指南）把"读得清"变成了有法律效力的硬指标。第 2 章讲过比值怎么算，这里是达标线：

几个最常见的翻车误区，条条见血：

  • 白底灰字到底能多灰？至少 #767676 才过 AA（约 4.54:1）；到处在用的 #999999 只有约 2.85:1，不合格。输入框占位符也算文本。

  • 细描边会被抗锯齿"冲淡"，实际观感低于计算值，宁可超标准一点。

4.4 色盲与色弱：每 12 个男性里约有 1 个分不清红绿

红绿色觉异常在北欧裔人群中约占男性 8%（1/12）、女性 0.5%，全球约 3 亿人。成因是 X 连锁隐性遗传——感知红绿的视锥细胞基因在 X 染色体上，所以男性远多于女性。分型上：绿色弱最常见（约 5% 男性），红/绿色盲各约 1–1.5%，红绿类合计占全部先天病例的 99%；蓝黄色盲罕见（约 0.008%），全色盲约 1/30000。

苹果与谷歌的灰阶分层与拟态用色
顶级系统的用色思路是"颜色为内容让路"——界面大面积保持中性，颜色只点在关键处，且每个颜色都是会自适应的"语义角色"。

5.1 Apple HIG：颜色不是色值，是"角色"

苹果设计的三条总原则：清晰、谦抑、纵深——UI 不与内容争艳，层级靠分层与动效表达。落到颜色上，最重要的思想是语义色：你不说"这里用 #000000"，你说"这里用 label（主文本）"——系统在浅色模式给黑、深色模式给白、"增强对比"辅助模式下自动加深。颜色是角色，不是色值。

文本层级就是一个现成的范本：主文本 label、次要文本 secondaryLabel（底色的 60% 透明度）、三级文本 tertiaryLabel（30%）——注意，苹果是用同一颜色的透明度阶梯而非不同的灰色值来表达层级，这样在任何背景色上都自动成立。背景分层同理：systemBackground（浅白/深黑）→ secondarySystemBackground（浅 #F2F2F7 / 深 #1C1C1E）→ tertiary（深 #2C2C2E），层级完全靠底色阶梯说话，不用阴影描边。

强调色同样是"角色"：systemBlue 在浅色模式是 #007AFF、深色模式自动换成更亮的 #0A84FF——深底上提亮，才能保证同样的可读性。苹果的官方提醒还包括：自定义颜色必须提供浅色、深色、增强对比三个变体；同一颜色不兼多义；不只靠颜色传信。

行话怎么说 语义色（Semantic Colors）；动态系统色（Dynamic System Colors）；材质（Materials）与鲜亮度（Vibrancy）：半透明毛玻璃层之上的前景色与背景动态混合，保证任何壁纸下都可读；2025 年 Liquid Glass（液态玻璃）把这套思路扩展为全局设计语言。

5.2 Material You：配色流水线

谷歌 Material Design 3 把配色做成了算法流水线：给一个种子色（甚至从你的壁纸里取），自动生成 tone 0（黑）到 100（白） 的明度阶梯，界面元素按"角色"领颜色。浅色主题主色用 tone 40，深色主题自动换 tone 80——深底上自动变浅变亮。

它的角色命名是一套自解释语法：on-* 是配对文字色（onPrimary 配 primary）、*Container 是容器填充、on*Container 配容器上的文字——按配对使用，无障碍对比自动合格。层级则靠 surfaceContainerLowest → Low → 默认 → High → Highest 五档明度阶梯表达，不再依赖阴影。动态取色时，语义色（错误红等）可锁定不参与变化。

5.4 玻璃拟态：为什么半透明卡片优于实色灰卡

玻璃拟态就是"磨砂玻璃卡片"：卡片半透明、背后内容被模糊，你能隐约看见后面的颜色和光，于是立刻知道"这层浮在那层上面"。配方四要素：

  1. 背景模糊（blur 12px 以上，移动端按性能预算收敛）；
  2. 半透明底色：白或黑，透明度约 10–40%；
  3. 细边高亮：1px 白色描边、透明度约 20–30%，模拟玻璃边缘的反光；
  4. 柔和阴影 + 大圆角。

对比实色灰卡，它赢在三处：保留上下文（空间层级一目了然）、让背景色彩渗透进来（画面是"活"的）、视觉重量轻。实色卡则像一堵墙，切断层级、增加沉重感，而且灰卡色值换一个背景就要重调。两个注意：背景必须有色彩或内容（纯白底上模糊无意义）；半透明底上的文字对比度要实测。这条脉络从 Windows Vista Aero（2007）→ iOS 7 vibrancy（2013）→ Windows 11 Mica（2021）→ Liquid Glass（2025）一路演化而来，也是开篇那个应用的设计规范里本就写明的方向——实色粉灰卡恰恰是对自己规范的违背。

行话怎么说 玻璃拟态（Glassmorphism）；背景模糊（Background Blur / backdrop-filter）；半透明（Translucency）。典型 CSS：background: rgba(255,255,255,.15); backdrop-filter: blur(12px);

5.5 深色模式：不是"把白的换成黑的"

苹果 WWDC 的原话：把深色模式想象成把灯光调暗，而不是把世界里外翻转。四条核心原则：

原则 1

不用纯黑 #000000

Material 推荐基础背景 #121212。纯黑三大问题：纯白文字 21:1 对比过强导致光晕与眼疲劳；OLED 像素完全熄灭再点亮产生滚动拖影；黑色上无法再压阴影，层级无从表达。
原则 2

层级 = 越高层越亮

深色下阴影看不见了，改用明度表达海拔：背景 #121212 → 卡片 #1E1E1E → 弹层 #2C2C2C → 最高层 #383838（Material 的做法是在基色上叠 4%/8%/12%/16% 白色覆盖层）。
原则 3

降低饱和度 20–40%

高饱和色在深底上会"闪"、产生视觉振动，还难过 4.5:1。深色模式的品牌色应"柔"而非"霓虹"——iOS 的 systemBlue 从 #007AFF 换成 #0A84FF 就是这个逻辑。
原则 4

文字层级用透明度，不用灰色值

Material：高强调白 87%、中强调 60%、禁用 38%；苹果 secondaryLabel 同理。同一颜色的透明度阶梯在任何深底上都成立，而固定灰色值换个底就翻车——和第 4 章"备注灰失效"是同一枚硬币的两面。

最后一条工程纪律：浅色深色各做一套色板，不做机械反色。反色会把"精心拉开的明度关系"整个颠倒——亮部变暗部，层级全乱。

行话怎么说 深色模式（Dark Mode）；海拔（Elevation）；光晕（Halation）：高对比白字在黑底上的"发光肿胀"感；OLED 拖影（Smearing）；表面覆盖（Surface Overlay）。

6.1 色温与白平衡：相机不会"脑补"

第 2 章讲过，大脑会自动把白纸看成白色（色彩恒常性）。相机不会——它只会老实记录光本来的颜色。白平衡就是你告诉相机"现在的光是什么色"，让它做反向补偿，把白的东西拍回白色。

色温用开尔文（K）刻度，典型值：烛火约 1900K、白炽灯 2700–3200K、正午日光 5500K、阴天 6000–7000K、阴影下可达 7000–9000K。最反直觉的一点：数值和体感相反——低 K 暖、高 K 冷。因为 K 值描述的是"黑体被烧到多少度发出这种光"：温度低烧出红橙光（烛火），温度极高才烧出蓝光（蓝色恒星）。相机白平衡口诀：相机 K 值 = 环境 K 值 → 还原正常；相机 K 值偏高 → 画面偏暖；偏低 → 偏冷。拍 RAW 格式，白平衡只是元数据，后期可以无损调整。

行话怎么说 色温（Color Temperature，单位 K）；白平衡（White Balance, WB）；黑体辐射（Black-body Radiation）：色温刻度的物理来源；显色指数（CRI）：1–100，光源还原真实色彩的能力。

6.3 调色流程：先"修"，后"调"

专业调色分两步。第一步校色（Color Correction）是技术活：把白平衡、曝光、对比调正确，让所有镜头看起来像同一天拍的——对应四个主色轮 Lift / Gamma / Gain（分别管阴影 / 中间调 / 高光）。第二步分级（Color Grading）是创作活：加风格加情绪，用 HSL 限定器（第 2 章那组曲线）做局部手术——只调肤色、只压天空。

两个高频名词：Log 是相机用对数曲线把大动态范围"压扁"记录下来的灰蒙蒙素材——画面发灰但细节全在，是"生肉"；LUT（查找表）是"输入颜色 → 输出颜色"的现成对照表，是"菜谱"。行业共识的操作顺序：白平衡 → 曝光对比 → 一级校色 → 二级调色 → 最后才低强度叠风格 LUT。跳过校色直接套 LUT，是新手最常见也最显眼的错误——菜谱救不了没洗的菜。

行话怎么说 色彩校正 vs 色彩分级（Color Correction vs Color Grading）；一级校色 / 二级调色（Primary / Secondary）；Log（对数曲线）；Rec.709：高清视频通用交付色彩空间；LUT（Look-Up Table）：分技术 LUT（Log→Rec.709 还原）、创意 LUT（风格）、输出 LUT（交付适配）。

6.4 摄影用光：灯是在给画面"上色"

三点布光定结构：主光（Key，相机侧 45°、高于眼睛 45°）定基调；辅光（Fill，强度约主光的 30–50%）柔化阴影；轮廓光（Back/Rim，50–100%）把人从背景里"剥"出来。色片（Gel）定颜色：CTO 橙片把日光色温的灯降到钨丝灯色，CTB 蓝片反向提升——混合光源场景的救场法宝；创意上，蓝片模拟月光、橙红片制造暖意，《银翼杀手 2049》的橙色拉斯维加斯就是大型橙色色片 + 烟雾做出来的。

两个免费黄金时段：黄金时刻（日出日落前后约 1 小时，色温偏暖 3000–4000K，人像绝配）；蓝调时刻（日落后约 20–40 分钟，天空是通透的深蓝、城市灯光初起）——"拍夜景要在天刚黑时拍"说的就是它，天全黑后天空就是一块死黑。

行话怎么说 三点布光（Three-Point Lighting）：主光 / 辅光 / 轮廓光（Key / Fill / Back Light）；光比（Lighting Ratio）；色片（Gel）与 CTO / CTB 校色温片；黄金时刻 / 蓝调时刻（Golden Hour / Blue Hour）。

6.5 AI 视频配色：模型听得懂行话，听不懂"好看一点"

AI 视频模型是按真实胶片和电影画面训练出来的，所以报"胶片名 + 调色术语"比堆形容词可靠得多。写"暖色调"是废话；写 teal-and-orange grade, lifted blacks, desaturated midtones, CineStill 800T 才是指令。常用胶片词：Kodak Portra 400（暖肤色、柔和，人像怀旧）、CineStill 800T（钨丝灯平衡 + 高光红色光晕，夜景/赛博朋克/王家卫感）、Kodak Vision3 500T（电影级剧情片感）、Fuji Pro 400H（冷调"日系"）。调色词：lifted blacks（抬黑位，胶片感）、muted film tones（低饱和胶片色调）、film grain（颗粒）。提示词公式：[主体+动作] → [镜头] → [光线氛围] → [胶片+调色] → [画幅]，每个词只干一件事；一条生成只押一种风格，混写必浑浊。（注：此领域快速演进，以 2025–2026 年主流模型实测为准。）

6.6 品牌色：视觉身份证

蒂芙尼蓝盒子不用看 logo 就知道是 Tiffany——它 1998 年注册了商标，由 Pantone 专门定制"1837 蓝"。可口可乐的设计系统白纸黑字写着 "We own red"。品牌色板的推导路径：取 LOGO 主色 → 按色轮关系选 1–3 个辅助色（邻近求和谐 / 互补求张力）→ 配黑白灰中性色打底 → 按 60-30-10 分配用量 → 写进品牌规范。最大错误是"选太多颜色"——主色 ≤2 个的品牌被认出的速度快 2–3 倍。

6.7 从照片提取色板：物以类聚

照片有上百万像素色，提取色板就是"聚类"——把相近的颜色归成几堆、每堆选代表。主流算法：中位切分（Median Cut）最快最稳定，K-Means 质量最高但慢，工程上常用"中位切分打底 + K-Means 精修"。注意：主色 ≠ 平均色——红蓝各半的图平均出来是图里根本不存在的脏紫色。Android 官方的 Palette API 更进一步：不只给一堆颜色，还按饱和度、亮度、像素占比三个维度打分，直接告诉你哪个适合当鲜艳主色（Vibrant）、哪个适合当柔和底色（Muted），甚至附带压在该色上可读的文字色。照片壁纸自动取主题色，靠的就是这套机制。

6.8 跨媒介一致性：一个色号走不了天下

同一个品牌蓝，屏幕上是"发光调色"、印刷是"油墨吸光"、视频是"广播标准"——三套规则互不相通，屏幕上的电光蓝油墨根本印不出来。所以专业品牌为每种媒介各存一份色值：HEX（网页）+ RGB（屏幕）+ CMYK（印刷）+ Pantone 编号（专色/包装），表格化写进 VI 手册。目标是"情绪冲击与识别度一致，而不是测量值一致"——像素级完全匹配在物理上不可能。屏幕端统一嵌 sRGB profile；印刷前软打样 + 超色域警告；绝不能错的品牌色（蒂芙尼蓝级别）上 Pantone 专色。

行话怎么说 颜色量化（Color Quantization）；K-Means / 中位切分（Median Cut）；Android Palette API 的六种色样（Swatch）：Light/Dark Vibrant + Light/Dark Muted + Vibrant + Muted；Pantone 专色（PMS Spot Color）；软打样（Soft Proofing）。

7.2 三个病因

病因 1 · 亮度关系

备注灰"踩线式合格"

4.74:1 只是数学上刚过 AA——那是"理想白底实验室"里的成绩。真机上还要打三折：OLED 低亮度呈色漂移（1.6 节）、抗锯齿把小字号笔画"冲淡"（4.3 节）、户外亮度压缩。有效对比度跌破 4.5:1，备注字就成了"淡墨写在毛边纸上"。教训：达标线要留余量，踩线等于不及格。
病因 2 · 色温关系

冷蓝图标 × 暖感灰卡 = 打架

#F7F7FA 的蓝分量仅比红绿高 3，理论上偏冷；但在 OLED 屏与纯白背景的"同时对比"（2.9 节）下，人眼实际感知为泛粉肉色的暖灰。高饱和冷蓝图标压上去，冷暖互斥 + 饱和度反差，产生第 3 章讲的视觉振动——这就是"看久了眼睛累"的来源。
病因 3 · 层级关系

卡片与背景"粘"在一起

卡片与白底仅 1.07:1——边界几乎全靠猜。苹果的做法是反转层级：背景用 Gray 6（#F2F2F7）、卡片用纯白（iOS 设置页即如此），分层差立刻拉开且永不显脏。而本设计在白底上放浅灰卡，方向反了，灰卡在白底"同时对比"下只会更显脏。
病因 0 · 理念层面

背离了自己的设计规范

该项目文档本就写明"苹果式拟态、半透明/透明卡片、iOS 玻璃质感"（5.4 节）。实色高灰度粉卡恰恰是对自家规范的违背——不是规范不对，是执行没跟上。

7.3 整改方案：四步到位

  1. 反转背景-卡片层级：背景改为 #F2F2F7（iOS Gray 6），卡片用纯白 #FFFFFF。分层差从 1.07:1 变成清晰的"灰底托白卡"，且不引入任何新色相。
  2. 备注文字加深：#6E6E73 → #48484A（卡片上对比度 4.74:1 → 8.53:1，超 AA 近一倍余量）；或改用 iOS 式语义色 #3C3C43（10.23:1）。
  3. 统一灰的冷暖：全站中性色统一带轻微冷感（与品牌蓝同温区），公式 hsl(220, 5–8%, L)——消除"粉肉色"观感的根。
  4. 中期向玻璃拟态演进：卡片改为半透明白（透明度约 60–75%）+ 背景模糊 + 1px 白色细边，回归项目既定设计规范（性能预算按"全屏至多一处实时模糊"执行）。
