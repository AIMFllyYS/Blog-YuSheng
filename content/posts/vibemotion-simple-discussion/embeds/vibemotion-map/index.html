VIBEMOTION · 你与 ChatGPT 的两轮对话 · 精炼为 17 个镜头

不要问「AI 会不会做这个动画」。先问：有没有一种表示方式，让 AI 很容易做它。

这是整场对话的核心原则。下面 17 个镜头，每个只讲一件事：一句结论 + 一个能动手玩的组件 + 几条要点。右侧导航可跳转，右下角的 Agent 可以就任意一章继续深挖。

Part I · 定义

它到底是什么，底层在做什么
SHOT 01 · 定义

VIBEMOTION 是什么

不是「AI 写代码生成视频」，而是：把视觉意图编译成一个可编辑、可执行、可确定性渲染的动态视觉系统。

两条管线
Prompt意图
场景 / 运动表示可计算的中间层
Code可编辑
Renderer可确定
Pixels视频

点一个框架，看它说的是哪种「视觉中间语言」
  • 多出来的中间层就是全部价值：可编辑、可复用、可局部修改。Prompt → Pixels 做不到「只改第 3 秒」。
  • Manim、Remotion、HyperFrames、Three.js、Blender 不是五个「视频软件」，而是五种视觉中间语言。
  • 开源生态里已有叫 Vibe Motion 的组织，定义是「Prompts → code → motion graphics」，下面已有 Remotion 脚手架、Skills、SRT → 分镜 → HyperFrames → FFmpeg 的项目。
SHOT 02 · 统一理论

视频 = 时间 → 场景状态

你说「视频的本质是蒙版 + 关键帧」——在 AE 体系里成立。再往下一层：关键帧只是定义 SceneState(t) 的一种方法，蒙版属于合成层。

拖动时间 · 换一种「定义状态」的方法
Frame(t) = Render( SceneState(t), Camera(t), Assets, Compositor, Seed )
t = 0.00s
00:01:06
SceneState(t) · 此刻的全部状态

  • 定义状态的方法远不止关键帧：数学函数、spring、物理、粒子、shader、rig、约束、状态机、路径跟随、音频驱动、程序噪声。
  • 所有框架都在解决同一件事：如何定义 SceneState(t)，如何把它渲染成 Frame(t)。这就是 VIBEMOTION 的统一理论。
  • 勾上「定格量化」：sampledT = floor(t × 12) / 12——定格不需要找一个 StopMotion.js，它是叠在任何渲染器上的时间量化。

Part II · 杠杆

为什么同一个模型，换个框架就像换了个人
SHOT 03 · Semantic Compression

语义压缩：Manim 为什么能抬高弱模型

不是 Manim 渲染更强，而是它替模型做掉了大量决策。模型只剩导演决策，不必重新发明动画工程。

同一句导演语言 · 需要模型自己决定多少件事
「一个公式从左边移到中央，然后某一项变红，再变形成另一个公式。」
14个实现决策，全由模型发明
搜索空间
  • Manim = 高语义压缩 · 强先验 · 小搜索空间。裸 React / HTML / Canvas / Three.js = 低压缩 · 高自由 · 大搜索空间。
  • 一句导演语言在裸框架下对应几十上百个实现决策；每个决策都是一次出错机会。
  • Manim 提供的不只是 API，而是一套领域本体（Domain Ontology）：数学动画世界已经替 AI 分好类了——MathTex、Transform、ReplacementTransform。
SHOT 04 · Framework Leverage

别比模型，测「模型 × 框架」

「这个模型不会做动画」，很多时候其实是：你让它在一个太宽的搜索空间里自己发明动画。

SHOT 05 · Seekable Deterministic Timeline

HyperFrames 的关键不在 HTML，在 seek(t)

时间被冻结：seek(0) 截一帧，seek(1/30) 截一帧……浏览器从网页播放器变成了确定性视频渲染器。

seek 模式 · seek(t) + 固定 seed
HyperFrames 官方 animation skill 统一接入的 runtime（可共存于同一 composition）
GSAPLottieThree.jsAnime.jsCSS KeyframesWeb Animations APITypeGPU
  • 任何库，只要能做到 seek(t) → 确定的一帧，理论上都能接进 VIBEMOTION。所以它更像「Web 动画运行时宿主」，不是「HTML 视频库」。
  • 要避开的三样：requestAnimationFrame、Date.now()、未固定 seed 的 Math.random()。
  • HeyGen 的方法论：判断框架是否「在和 Agent 对抗」——看是不是必须用最强模型才能出可用结果。他们围绕 Gemini Flash 能稳定写出的东西收紧 authoring model，跨模型 eval，失败在哪就收紧 runtime 和 Skills。

Part III · 边界

AI 到底能做到哪里，边界怎么被推开
SHOT 07 · Boundary Engineering

「AI 的边界」其实有七种

你要的不是「裸模型能力」，而是：给 AI 配上某种现成能力后，它能稳定做到什么程度。每种边界都能被工程手段缩小。

选一种边界 · 看它怎么翻车、用什么缩小
  • AI 明明「会 Three.js」，做复杂 3D 却穿模、摄影机乱、比例怪——未必是不会 3D，而是缺少 constraint / collision / rig / camera preset 等中间先验。
  • Boundary Engineering：不只等模型变聪明，而是主动改变模型要解决的问题。
SHOT 08 · Capability Atlas

能力元素周期表

组件库不是工具箱，而是被前人编码好的专业知识。研究的最小单位不是「框架」，而是「它白送了 AI 哪个 primitive」。

点一个元素 · 打开它的鉴定卡
  • 看到一个库，别问「能不能用它做视频」——几乎都能。要问：它给 AI 增加了哪个以前很难实现的 primitive？
  • 很多材料本来不是为视频发明的：Two.js 自称深受 flat motion graphics 启发；EffectComposer 像 AE 的效果堆栈；PlayCanvas 已有 HDR Bloom、SSAO、DOF、LUT。
  • 认知边界案例：不知道 gl-transitions，会以为高级转场需要很强的 shader 能力；知道以后，只需选对 transition + 调几个 uniform。
SHOT 09 · 鉴定师审批

写「Agent 使用说明书」，不写 API 文档

API Skill 教 AI 当程序员；Grammar Skill 教 AI 当导演。模型本来就会调 API，稀缺的是：什么时候值得用、什么时候千万别用。

Cinematography

  • 只做「搜 GitHub → 把 README 塞进 Skill」，最后得到一个巨大的垃圾知识库。价值在于经过实际渲染验证的能力图鉴。
  • 每个组件一张鉴定卡，固定字段：原子能力、最适合场景、视觉上限、AI 友好度、首次成功率、组合能力、Seek 能力、高级效果、失败模式、平庸模式、最佳 Recipes、模型测试、实际 Demo、已有 Skill、证据状态。
  • 这不是在定义新标准，只是统一记录研究结果。

SHOT 12 · 看片 → 拆效果 → 找库

拉片反拆：一个镜头 = 一组能力原子

不要把一个镜头总结成「Vox 风」。拆成可搜索的能力原子，每个原子都能反查到一个已经解决它的库。

一个 Vox 式镜头 · 逐拍 seek

SHOT 14 · 路线修正

不统一技术，只统一认知

第一轮 ChatGPT 建议造 Motion IR。你的反驳成立：时间有限，现在定义标准只会用有限的认知提前框死未来。先大规模摸边界，最优结构会自己浮出来。

  • 要建的不是「最佳视频工作流」，而是 Code Motion Capability Atlas（代码动画能力图鉴）。原则：允许重复、允许矛盾、允许暂时没有统一答案。
  • 你的炼丹比喻：主角的炼丹能力，取决于他能把多少药材的特性列举全面。维护最全的 Skills 集 + 最全的组件库集，给效果分级（有创意的 / 安全的 / 平庸的），再让 AI 渐进式披露。
  • 你要成为的是 AI Motion Capability Generalist：知道世界上有哪些能力、大概在哪、模型何时能稳定调用、哪几样组合会质变。
SHOT 15 · 任务 × 模型 × 库 × Skill

固定变量，才知道增益来自哪里

同一素材、同一脚本、同一视觉目标、同一时长。否则根本分不清差距来自模型、Prompt、Skill、库，还是第一次运气好。

实验矩阵 · 点格子记录结果（仅存本浏览器）

点击循环：未测 → 翻车 → 可用 → 惊艳。看哪一列（库）让弱模型的格子也变绿——那就是高杠杆材料。

以前人类 benchmark 前端库看 fps / bundle / 内存；AI-native 库要多一个维度：Model Compatibility。

  • Revision Test 最关键：「只把第 3 镜节奏提高 30%，其余不要变。」能不能进生产，不看第一次能不能做出来，看修改是否局部、稳定、可控。
  • 有些库人类觉得很牛，却不适合 AI；有些看起来很简单，却极度适合 AI——后者是金矿。
  • 你本来就有自媒体渠道：每一次「做一个新风格视频」，本身就是一次 benchmark。
SHOT 16 · Flywheel

飞轮与护城河

内容生产 = 研究，研究 = Skill 数据，Skill 数据 = 下一次质量。护城河不是代码，是经过实际视频生产验证的能力知识库。

四个环节 · 循环而非排期
同一个模型 · 两种上下文
