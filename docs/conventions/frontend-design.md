> **原型就是全站模板。** 绳挂导航、下落便签通知、弹窗、抽屉、滚动条、便笺提示、组件卡片，其它页面（含未来 `/notes/` `/works/` `/about/`、404、登录）只换内容，不另做一套皮肤。本文不为这些外壳再写第二份外观。

## 一、主题系统

### 1.1 预设主题

四套主题通过 `<html data-theme="...">` 切换：

| data-theme | 名称 | 定位 |
|---|---|---|
| `paper` | 宣纸黄 | 默认。书卷清新，全站基调 |
| `mist` | 浅蓝 | 清晨雾青 |
| `snow` | 米白 | 纯净亮色 |
| `night` | 纯黑 | 夜间模式 |

### 1.2 主题作用范围 ✅

- **主题只作用于常规页面**（阅读页、列表页、设置面板等）
- **首页 3D 叙事场景固定一套视觉**，像电影片头一样精心调好不随主题变——避免 3D 场景做四套灯光/材质的成本
- 首页中的 UI 挂件（导航、按钮）仍走 token，与当前主题保持一致

### 1.3 颜色 token

所有颜色走 CSS 变量语义 token，**任何组件禁止硬编码颜色**：

```css
--bg              /* 页面底色 */
--bg-elevated     /* 浮起面板（评论区、目录）底色 */
--ink             /* 正文文字 */
--ink-muted       /* 次要文字 */
--ink-faint       /* 辅助/占位文字 */
--accent          /* 强调色（链接、选中态、金光元素的 UI 呼应） */
--line            /* 分隔线/描边 */
--highlight       /* 划词注释的高亮底色 */
--annotation      /* 注释徽标、锚点和选中态 */
--comment         /* 文章评论入口和状态 */
--author-badge    /* 作者身份徽标 */
--scroll-paper    /* 卷轴/纸张材质类组件的专用底色 */
--shadow-color    /* 阴影基色（night 主题下阴影策略不同） */
```

命名规则：**语义命名，不用色值命名**（`--accent` 而非 `--gold-500`），换主题只改变量值。token 清单随开发滚动扩充，扩充时更新本文档。

首页电影化叙事固定使用以下场景语义 token，不受四套常规主题切换影响；3D 材质、DOM 字幕与场景特效必须共同引用它们：

```css
--journey-void        /* 深空底色 */
--journey-void-raised /* 抬升的深空层 */
--journey-gold        /* 核心金光 */
--journey-gold-soft   /* 柔和金光与星点 */
--journey-paper       /* 古书纸面 */
--journey-paper-edge  /* 书页边缘与装订 */
--journey-ink         /* 纸面墨色 */
```

## 二、字体

- **字体走云字体服务，不自托管**：字体文件不进仓库、不进 `public/fonts/`、不进 `out/`——EdgeOne 的空间与 20,000 文件数限制不允许承载大中文字体及其上百个切片。选用国内可达的云字体 CDN；**不依赖 Google Fonts**（国内可达性差），但也不限定于 Google 系字体
- **正文与标题：衬线字（宋体系）**——与宣纸/书卷氛围统一。候选：思源宋体（Source Han Serif SC，开源、多数云字体服务可分发）
  - ⚠️ 中文字体动辄 10–20MB，比全站 JavaScript 重一个量级，**必须按 `unicode-range` 切片加载**：切片与分发由云字体服务商承担，浏览器只下载当前页面命中的那几片；选服务商时必须确认其提供 `unicode-range` 切片式 CSS，而不是整包 woff2
  - ⚠️ **不要按"站内已用字"整体裁剪**：文章用字构建期可知，但评论/注释的字符集由访客决定，构建期不可知；整体裁剪会让讨论区出现缺字
  - 服务商选定须验证：国内访问延迟、HTTPS、字体许可证允许 Web 分发、切片粒度；选定结果与接入方式记录到本文档
  - 降级栈：`"Source Han Serif SC", "Noto Serif SC", serif`，字体加载完成前用系统衬线过渡（`font-display: swap` 语义），不阻塞文字显示
  - 首屏字体体积上限见 [内容引擎规格 13.2 性能预算](../specs/blog-content-engine.md#132-性能预算)，计量对象是云字体实际命中的切片流量
- 附魔台文字效果需一款符文风格展示字体（仅首页装饰用，同样走云字体或极小 subset）
- 代码块：等宽字体（JetBrains Mono 或系统等宽栈）
- 导出（PDF/DOCX）需要覆盖任意访客用字，只能用完整中文字体；它与阅读用切片分开计量，仅在触发导出时从 CDN 拉取，不打进仓库或静态产物

## 三、动效规范

全站 UI 动效是**阻尼、慢、ease-out**，用来塑温馨、书卷、不慌。实现时对照原型里已经在用的曲线和追赶系数，不要按「更利落」自行加快。

### 3.0 动效语言

- **默认位移曲线** `--ease-damp`：`cubic-bezier(.22, .82, .28, 1)`。栏宽、挂签、抽屉、右栏缓出、较大位移都走它。
- **含义菜单弹出** `--ease-pop`：`cubic-bezier(.34, 1.22, .42, 1)`，配 `--dur-pop`（480ms）。导出、设置、笔菜单、登录/关于弹窗、图形图例卡，统一**缓动放大 + 一次很小的过冲**。这是菜单专用，不是全站弹簧。
- **Tab 切换**：微缓动（`--ease-damp`）+ 约 380–400ms 短骨架懒载，再淡入真内容。不要套整栏 `--dur-reveal`。
- **颜色 / 透明度**可用普通 `ease-out`，不要用阻尼曲线去「弹」透明度。
- **连续量**（页尾 `--reveal`、点「去页尾」的滚动）每帧按约 **0.035** 追赶目标，读起来像被轻轻拽住；禁止一步跳到 1。
- **允许的轻摆**：绳、笔这类氛围循环可以慢晃（数秒一圈）。这是呼吸，不是点击反馈。
- **禁止**：大块栏/页尾弹簧回弹、`bounce` / `elastic`、猛的 snap、为了「活泼」把大位移砍到 150ms 以下。菜单那一次小过冲不算违规。
- **其它例外**：进页书册翻页严格跟 Uiverse Nawsome 原作；通知下落是重力 + 轻摇，落地后隐去，不是弹跳落地。
- **首页 3D 叙事**可以更有戏剧性（金光、穿门），但入门之后的绳挂、通知、面板仍走本节语言，不能把片头的爆发带进常规 UI。

### 3.1 时长 token

| Token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 150ms | 悬停变色、按钮反馈；只用于小状态，不用来推栏 |
| `--dur-base` | 250ms | 导航渐隐、轻量显隐 |
| `--dur-slow` | 400ms | 主题切换过渡、大面积颜色转场 |
| `--dur-reveal` | 780ms | 右栏/抽屉等大块缓出；必须配 `--ease-damp` |
| `--dur-pop` | 480ms | 含义菜单放大弹出；Tab 短骨架也用这一档 |
| `--ease-damp` | `cubic-bezier(.22, .82, .28, 1)` | 全站大位移默认曲线 |
| `--ease-pop` | `cubic-bezier(.34, 1.22, .42, 1)` | 菜单专用：放大 + 一次小回弹 |

### 3.2 分层归属（与技术栈对应）

| 层 | 工具 | 管什么 |
|---|---|---|
| L1 微交互 | CSS transition + Tailwind | 悬停、收展、渐隐；曲线按 3.0 |
| L2 编排动画 | GSAP + ScrollTrigger | 首页滚动叙事、文字效果（拆散/附魔乱码） |
| L3 3D 场景 | Three.js via R3F + drei | 立体书、摄像机、金光（只在首页叙事） |
| 绳索摆动 | 轻量 verlet 或 SVG+GSAP | 绳挂导航的慢摆（不引入完整物理引擎） |

规则：一个动画只归一层，禁止跨层混写。L1 禁止用 GSAP 做按钮/面板。L2/L3 的戏剧性停在首页叙事，不泄漏到阅读页 chrome。

### 3.3 可访问性

- **`prefers-reduced-motion` 全站尊重**：装饰性动画停用，功能性过渡缩短或直达终态
- 主题切换用全局 400ms 颜色过渡，避免闪跳

## 四、层级（z-index）表

统一层级表，禁止随手写 z-index 数字：

| 层 | 值 | 内容 |
|---|:---:|---|
| base | 0 | 正文内容 |
| panel | 10 | 左目录 / 右侧评论、注释、Agent 工作区 |
| floating | 20 | 收起后的右侧悬浮小笔 / 移动端目录入口 |
| nav | 30 | 顶部绳挂导航（渐隐层） |
| overlay | 40 | 弹窗 / 抽屉遮罩 |
| toast | 50 | 全局通知 |
| boot | 60 | 进入博客页的书册遮罩；揭开后移除 |

**渐隐层的命中区规则 ✅**：顶部绳挂导航是横贯整屏、约 88px 高的固定层，正下方压着左右栏页签与正文顶部。容器与装饰（绳索、挂钩、占位）必须 `pointer-events: none`，只有挂件本身在导航可见时可点，弹出面板只在打开时可点。鼠标唤出范围再收一刀：只认中栏顶部，左右栏顶部不唤出。否则左右栏页签点不动、正文顶部无法划词，而且因为导航是渐隐的极难排查。

## 四之二、滚动条

- 每套主题各出两个滑块颜色 token（常态 / 悬停），取 `--ink` 系低透明度值，不引入新色
- **静止时完全透明**，指针进入可滚动容器才浮现无轨细滑块，离开即隐去
- 左栏目录模式与中栏禁止彻底隐藏——长文的滚动位置是必要信息
- **例外，彻底不画**：窗体最右侧（`html` / `body`）与右栏工作区；图形模式左栏同样隐去。页尾与右栏仍可滚轮滚动
- 同时写 `scrollbar-color`（Firefox）与 `::-webkit-scrollbar-*`；滑块用透明边框 + `background-clip: content-box` 内缩

## 四之三、通知（toast）

全站轻量反馈只有这一种形态：**会自己往下落的纸质通知**。视觉与交互以 [blog-reader-prototype.html](../designs/blog-reader-prototype.html) 为准。评论发布成功、注释写下、复制链接、导出完成、登录邮件已发送、首页或其它板块的轻量成功提示，都走这一套。禁止再做右上角角标、系统 snackbar、或按页面换一套通知。

- `--scroll-paper` 底、`--line` 边框、顶部半透明胶带、右下折页、轻微倾斜
- 一行「通知」抬头 + 一句正文
- 从视口顶出现后受重力落到最底部，然后隐去；下落过程带轻微摇摆
- 左右落点随机，起始高度相同；可同时存在多张，互不影响
- 整套通知默认 1 秒冷却，冷却期内不再生成新便签，防止高频点击
- 鼠标悬停即停住（也可把正在隐去的通知重新拿住）；移开后继续下落
- 点击后撕成碎片散开再隐去；不引入 Three.js——通知是两秒级反馈，3D 运行时留给首页叙事
- `role="status"`，不抢焦点；需要决策的失败走弹窗或就地状态
- `prefers-reduced-motion` 下取消下落与撕碎，只做显隐
- 层级走 `--z-toast`（50），避开绳挂导航与右侧悬浮小笔

## 四之四、全站共用外壳（以原型为模板）

下面这些东西全站只有一套。形态、间距、动效以 [blog-reader-prototype.html](../designs/blog-reader-prototype.html) 为准；`blog-reader-design.md` 只解释阅读页为什么这样，不授权其它页面另起炉灶。

| 外壳 | 唯一模板 | 禁止另做 |
|---|---|---|
| 绳挂导航 | 顶绳 + 卷轴/书签/圆挂牌，渐隐，命中区见第四节 | 长方形顶栏、胶囊 Tab、汉堡条当主导航 |
| 通知 | 下落便签（四之三） | 角标、snackbar、系统灰条 |
| 便笺提示 | 挂件正下方倾斜小纸片 | 黑底 tooltip、浏览器 `title` 当主提示 |
| 弹窗 | 纸面居中卡 + 遮罩（登录、关于） | 系统 `alert` / `confirm` 当主流程 |
| 抽屉 | 左右滑出 + 同一遮罩；右栏骨架缓出 | 底栏 sheet 另套皮肤 |
| 滚动条 | 静止隐去，例外处彻底不画（四之二） | 系统灰槽常驻 |
| 正文组件卡 | 细边、`--bg-elevated`、顶栏标题 + 徽标 | 每种 renderer 自己画一张卡 |
| 进页遮罩 | 书册 + 浅印章（第十一节） | 按页面换一套 spinner |

未单独出原型的页面（`/notes/` `/works/` `/about/`、404、loading）先复用上表，只换文案与内容，不先发明新外壳。

## 五、响应式与移动端策略

- 断点沿用 Tailwind 默认（sm 640 / md 768 / lg 1024 / xl 1280）
- **首页移动端降级 ✅**：检测到移动设备（视口/指针类型，客户端判定）时不加载 3D 叙事，直接显示**经典卡片式板块入口**（博客/短随笔/作品集/关于我 + 主题与音效挂件）；移动端用户以读文章为主，入口效率优先
- 阅读页三栏：>1024px 三栏可拉动（左栏常驻不可收起，右栏可收为**右侧**悬浮小笔）；≤1024px 左右栏都收成抽屉，从左下文字球 / 右侧小笔呼出，整幅页尾评论区成为评论主入口
- 阅读页是**双层滚动**：三栏各自 `height:100vh; overflow:auto`。首屏只显示三栏；正文到底先收口，继续下滚才把页尾拉出。中栏不要设 `overscroll-behavior: contain`，否则滚不到页尾（详见 [blog-reader-design.md 3.1](../designs/blog-reader-design.md)）
- 3D/GSAP 相关代码全部动态 import，移动端首页不下载 3D 资源（不只是不渲染）
- 3D 场景运行时必须：标签页不可见时暂停、滚动离开首屏后暂停、帧率不足时自动降档（减少粒子/关闭后处理），不硬扛低端集显
- 各场景体积上限与实测要求见 [内容引擎规格 13.2 性能预算](../specs/blog-content-engine.md#132-性能预算)

## 六、阅读页评论、注释与划词交互

### 6.1 概念与入口

- **评论**针对整篇文章，通过评论入口打开右侧评论区；不依赖文字选区。
- **注释**针对一个稳定文本选区；用户划词后在 WPS 风格浮动工具条中点击“注释”，打开右侧注释区并带入选区。
- 划词工具条固定为：复制 / 询问（接口占位）/ 注释。不得再次提供“发布注释/发布评论”切换。
- 右侧工作区用清晰页签区分评论、注释和未来 Agent；共享线程视觉不等于混淆产品概念。

### 6.2 注释列表与正文高亮

- 注释列表默认按正文锚点从上到下排列；同一锚点内按创建时间排列。
- 点击注释时滚动并强调正文目标；点击正文高亮时定位右侧对应注释。
- 同一目标存在多条注释时，以一个稳定高亮承载数量提示，避免叠加多层不可辨识底色；最终聚合交互在实现验收时确认。
- 失锚注释不得静默消失，应在注释列表显示可理解的“原文位置已变化”状态。

### 6.3 作者与访客徽标

- 每条评论、注释和回复显示“作者”或“访客”小徽标。
- 徽标由认证系统的已验证邮箱与作者白名单比较后派生，用户不能自行选择。
- 不在前端显示登录邮箱；只显示公开名称、徽标和时间。
- 徽标只表达身份，不引入等级、积分、认证层级或社交关系。

### 6.4 编辑和删除反馈

- 用户只能编辑自己的内容；编辑后可显示轻量“已编辑”提示，不展示历史版本。
- 删除根线程会删除全部回复，执行前必须清楚提示影响范围并二次确认。
- 作者可以删除任意讨论内容，但不能编辑他人的文字。
- 删除为硬删除，不显示墓碑或回收站入口。

### 6.5 讨论内容渲染

- 评论和注释复用统一 `DocumentRenderer`，使用更严格的 `discussion` profile。
- 允许安全 Markdown、代码、表格、KaTeX、严格模式 Mermaid；注册组件还必须进入集中 allowlist，v1 不开放讨论区 Canvas 或问答题。
- 禁止原始 HTML、任意脚本/样式、图片、音视频、SVG/HTML/网页嵌入和任意动态模块路径。
- 遇到禁止组件时在发布前给出明确错误，不静默删除用户内容。

## 七、导出交互

- 导出入口是一级菜单；Markdown 二级菜单提供纯正文、正文+注释、正文+评论、正文+注释+评论。
- TXT、DOCX、PDF 使用相同内容范围选择；问答题可增加“包含答案与解析”开关。
- PDF 点击后直接生成并下载，不调用 `window.print()`、系统打印机或 Windows 打印对话框。
- 生成期间显示可取消的进度状态；失败时说明具体组件或资源，不只显示“导出失败”。
- 含讨论导出必须显示快照时间；讨论读取失败或超过上限时让用户明确选择重试、分卷或仅正文，不得把不完整文件标成“全部导出完成”。
- 导出相关代码动态加载，不进入普通阅读首屏包。

## 八、音效规范

- 全部音效经 `src/lib/audio/` 统一播放，受全局开关（导航挂件）控制，默认**关闭**（尊重访客）
- UI 音效放 `public/sounds/`，单文件短小（<100KB 量级）
- 具体触发点位与素材来源待后续轮次定

## 九、决策理由

- **语义 token**：四主题切换 + 未来自定义主题，只有语义层能做到"换主题不改组件"
- **首页固定视觉**：3D 场景是"作品"不是"界面"，一套精调视觉的品质远高于四套仓促适配；成本降低 75%
- **移动端卡片入口**：移动端跑 3D 的代价（发热/耗电/流量/低端机卡顿）远大于收益，直达内容才是移动场景的真实需求
- **统一 z-index 表**：多浮层产品（导航/面板/悬浮球/弹窗）最易层级打架，提前立表成本几乎为零
- **阻尼动效 + 共用外壳**：温馨来自慢和被拽住的感觉，不来自弹跳；通知/导航/弹窗全站一套，比每页「优化一版」便宜且统一
- **统一渲染器、不同 profile**：文章和讨论共享能力实现，但用户内容只能调用经过明确允许的安全子集
- **评论与注释分区**：文章级讨论和选区级批注拥有不同入口与排序语义，不能用一个发布类型开关混在一起
- **图形目录是骨架尺，不是第二棵树**：篇幅对比必须一眼可读；压缩到各节同高等于丢掉这根尺

## 十、博客阅读页图形目录（原则）

外观仍 **1:1 对标** [blog-reader-prototype.html](../designs/blog-reader-prototype.html)，细节说明见 [blog-reader-design.md](../designs/blog-reader-design.md)。本文只锁产品原则，落地时不得另写一套节点皮肤。

- 图形模式把整篇文章缩成一张可点击的骨架屏：每个一级章节一张卡片，标题行统一，正文是堆叠的骨架条。
- **文字越长，条越多。** 计量用该节去空白字数（含该节下的二三四级），不按标题层级再拆节点。
- 条数在**一篇文章内部相对映射**：最短的节最少、最长的节最多，中间线性插值（2–8 条）。末条宽度表示余数。禁止开方或其它把各节压成同一档的算法。
- 自定义标签 / 图片 / 思维导图三类微标只挂在一级标题行，各用 `--accent` / `--annotation` / `--comment`。音频不进微标。
- 虚线视口框只定位当前阅读位置，高度不随章节篇幅缩放。

## 十一、博客进页与右栏动效（原则）

外观仍 **1:1 对标** [blog-reader-prototype.html](../designs/blog-reader-prototype.html)。本文只锁原则。

- 进入 `/blog/` 与 `/blog/<slug>/` 时先盖一层全屏书册遮罩，再揭开页面。书册 HTML/CSS **严格**跟 Uiverse Nawsome 原作（`.loader`、六页、只翻 2–5 页）；只把 `--background` / `--shadow` / `--page` / `--page-fold` / `--text` 映射到当前主题 token，禁止原作蓝紫，也禁止改动画结构。
- 遮罩四周可用 Pretext Two（`prepareWithSegments` + `layoutNextLineRange`）量「羽升」后按视口中心铺格，绕开书册，极浅并带软光；不进正文包。单页 HTML 用 `esm.sh` 钉版本，禁止 `unpkg` 拉 TypeScript 入口。
- 这层遮罩是路由进入一次；主题切换、打开右栏、导出等页内操作不再重放。
- 右栏展开/收起用 `--dur-reveal` + `--ease-damp` 缓出：先出与当前页签同构的骨架，栏宽到位后再淡入真内容。骨架条用百分比宽度，跟着栏一起适配。不要弹跳。
- `prefers-reduced-motion` 下取消翻页与骨架闪动，直接到终态。
- 书册遮罩层级走 `--z-boot`（60）。
