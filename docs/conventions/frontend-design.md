## 一、主题系统

### 1.1 预设主题

四套主题通过 `<html data-theme="...">` 切换：

| data-theme | 名称 | 定位 |
|---|---|---|
| `paper` | 宣纸黄 | 默认。书卷清新，全站基调 |
| `mist` | 浅蓝 | 清晨雾青 |
| `snow` | 米白 | 纯净亮色 |
| `night` | 纯黑 | 夜间模式 |

### 1.2 主题作用范围 ✅

- **主题只作用于常规页面**（阅读页、列表页、设置面板等）
- **首页 3D 叙事场景固定一套视觉**，像电影片头一样精心调好不随主题变——避免 3D 场景做四套灯光/材质的成本
- 首页中的 UI 挂件（导航、按钮）仍走 token，与当前主题保持一致

### 1.3 颜色 token

所有颜色走 CSS 变量语义 token，**任何组件禁止硬编码颜色**：

```css
--bg              /* 页面底色 */
--bg-elevated     /* 浮起面板（评论区、目录）底色 */
--ink             /* 正文文字 */
--ink-muted       /* 次要文字 */
--ink-faint       /* 辅助/占位文字 */
--accent          /* 强调色（链接、选中态、金光元素的 UI 呼应） */
--line            /* 分隔线/描边 */
--highlight       /* 划词注释的高亮底色 */
--annotation      /* 注释徽标、锚点和选中态 */
--comment         /* 文章评论入口和状态 */
--author-badge    /* 作者身份徽标 */
--scroll-paper    /* 卷轴/纸张材质类组件的专用底色 */
--shadow-color    /* 阴影基色（night 主题下阴影策略不同） */
```

命名规则：**语义命名，不用色值命名**（`--accent` 而非 `--gold-500`），换主题只改变量值。token 清单随开发滚动扩充，扩充时更新本文档。

首页电影化叙事固定使用以下场景语义 token，不受四套常规主题切换影响；3D 材质、DOM 字幕与场景特效必须共同引用它们：

```css
--journey-void        /* 深空底色 */
--journey-void-raised /* 抬升的深空层 */
--journey-gold        /* 核心金光 */
--journey-gold-soft   /* 柔和金光与星点 */
--journey-paper       /* 古书纸面 */
--journey-paper-edge  /* 书页边缘与装订 */
--journey-ink         /* 纸面墨色 */
```

## 二、字体

- 字体文件自托管放 `public/fonts/`（EdgeOne 国内访问，不依赖 Google Fonts）
- **正文与标题：衬线字（宋体系）**——与宣纸/书卷氛围统一。候选：思源宋体（Source Han Serif SC，开源可自托管）
  - ⚠️ 中文字体动辄 10–20MB，比全站 JavaScript 重一个量级，**必须按 `unicode-range` 切片自托管**：切成上百个字符区间分片，浏览器只下载当前页面命中的那几片，这是实现期硬性工序
  - ⚠️ **不要按"站内已用字"整体裁剪**：文章用字构建期可知，但评论/注释的字符集由访客决定，构建期不可知；整体裁剪会让讨论区出现缺字
  - 降级栈：`"Source Han Serif SC", "Noto Serif SC", serif`，字体加载完成前用系统衬线过渡，不阻塞文字显示
  - 首屏字体体积上限见 [内容引擎规格 13.2 性能预算](../specs/blog-content-engine.md#132-性能预算)
- 附魔台文字效果需一款符文风格展示字体（仅首页装饰用，subset 后体积可控）
- 代码块：等宽字体（JetBrains Mono 或系统等宽栈）
- 导出（PDF/DOCX）需要覆盖任意访客用字，只能带完整中文字体；它与阅读用切片分开计量，仅在触发导出时加载

## 三、动效规范

### 3.1 时长 token

| Token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 150ms | 悬停、按钮反馈 |
| `--dur-base` | 250ms | 面板收展、导航渐隐 |
| `--dur-slow` | 400ms | 主题切换过渡、大面积转场 |

### 3.2 分层归属（与技术栈对应）

| 层 | 工具 | 管什么 |
|---|---|---|
| L1 微交互 | CSS transition + Tailwind | 悬停、收展、渐隐 |
| L2 编排动画 | GSAP + ScrollTrigger | 滚动叙事、文字效果（拆散/附魔乱码） |
| L3 3D 场景 | Three.js via R3F + drei | 立体书、摄像机、金光 |
| 绳索摆动 | 轻量 verlet 或 SVG+GSAP | 绳挂导航（不引入完整物理引擎） |

规则：缓动默认 `ease-out` 系；弹性/摆动类由 GSAP 管，不写 CSS；一个动画只归一层，禁止跨层混写。

### 3.3 可访问性

- **`prefers-reduced-motion` 全站尊重**：装饰性动画停用，功能性过渡缩短
- 主题切换用全局 400ms 颜色过渡，避免闪跳

## 四、层级（z-index）表

统一层级表，禁止随手写 z-index 数字：

| 层 | 值 | 内容 |
|---|:---:|---|
| base | 0 | 正文内容 |
| panel | 10 | 左目录 / 右侧评论、注释、Agent 工作区 |
| floating | 20 | 收起后的右下批注球 / 移动端目录入口 |
| nav | 30 | 顶部绳挂导航（渐隐层） |
| overlay | 40 | 弹窗 / 抽屉遮罩 |
| toast | 50 | 全局通知 |

**渐隐层的命中区规则 ✅**：顶部绳挂导航是横贯整屏、约 88px 高的固定层，正下方压着左右栏页签与正文顶部。容器与装饰（绳索、挂钩、占位）必须 `pointer-events: none`，只有挂件本身在导航可见时可点，弹出面板只在打开时可点。否则左右栏页签点不动、正文顶部无法划词，而且因为导航是渐隐的极难排查。

## 四之二、滚动条

- 每套主题各出两个滑块颜色 token（常态 / 悬停），取 `--ink` 系低透明度值，不引入新色
- **静止时完全透明**，指针进入可滚动容器才浮现无轨细滑块，离开即隐去
- 禁止 `scrollbar-width: none` 或彻底隐藏——长文的滚动位置是必要信息
- 同时写 `scrollbar-color`（Firefox）与 `::-webkit-scrollbar-*`；滑块用透明边框 + `background-clip: content-box` 内缩

## 四之三、通知（toast）

全站轻量反馈统一为**会自己往下落的纸质通知**，可同时多张，视觉与交互以 [blog-reader-prototype.html](../designs/blog-reader-prototype.html) 为准。评论发布成功、注释写下、复制链接、导出完成、登录邮件已发送都走这一套，禁止再做一套右上角角标或系统灰条。

- `--scroll-paper` 底、`--line` 边框、顶部半透明胶带、右下折页、轻微倾斜
- 一行「通知」抬头 + 一句正文
- 从视口顶出现后受重力落到最底部，然后隐去；下落过程带轻微摇摆
- 左右落点随机，起始高度相同；可同时存在多张，互不影响
- 整套通知默认 1 秒冷却，冷却期内不再生成新便签，防止高频点击
- 鼠标悬停即停住（也可把正在隐去的通知重新拿住）；移开后继续下落
- 点击后撕成碎片散开再隐去；不引入 Three.js——通知是两秒级反馈，3D 运行时留给首页叙事
- `role="status"`，不抢焦点；需要决策的失败走弹窗或就地状态
- `prefers-reduced-motion` 下取消下落与撕碎，只做显隐
- 层级走 `--z-toast`（50），避开绳挂导航与右下批注球

## 五、响应式与移动端策略

- 断点沿用 Tailwind 默认（sm 640 / md 768 / lg 1024 / xl 1280）
- **首页移动端降级 ✅**：检测到移动设备（视口/指针类型，客户端判定）时不加载 3D 叙事，直接显示**经典卡片式板块入口**（博客/短随笔/作品集/关于我 + 主题与音效挂件）；移动端用户以读文章为主，入口效率优先
- 阅读页三栏：>1024px 三栏可拉动（左栏常驻不可收起，右栏可收为悬浮球）；≤1024px 左右栏都收成抽屉，从悬浮球呼出，整幅页尾评论区成为评论主入口
- 阅读页是**双层滚动**：三栏各自 `height:100vh; overflow:auto`。首屏只显示三栏；正文到底先收口，继续下滚才把页尾拉出。中栏不要设 `overscroll-behavior: contain`，否则滚不到页尾（详见 [blog-reader-design.md 3.1](../designs/blog-reader-design.md)）
- 3D/GSAP 相关代码全部动态 import，移动端首页不下载 3D 资源（不只是不渲染）
- 3D 场景运行时必须：标签页不可见时暂停、滚动离开首屏后暂停、帧率不足时自动降档（减少粒子/关闭后处理），不硬扛低端集显
- 各场景体积上限与实测要求见 [内容引擎规格 13.2 性能预算](../specs/blog-content-engine.md#132-性能预算)

## 六、阅读页评论、注释与划词交互

### 6.1 概念与入口

- **评论**针对整篇文章，通过评论入口打开右侧评论区；不依赖文字选区。
- **注释**针对一个稳定文本选区；用户划词后在 WPS 风格浮动工具条中点击“注释”，打开右侧注释区并带入选区。
- 划词工具条固定为：复制 / 询问（接口占位）/ 注释。不得再次提供“发布注释/发布评论”切换。
- 右侧工作区用清晰页签区分评论、注释和未来 Agent；共享线程视觉不等于混淆产品概念。

### 6.2 注释列表与正文高亮

- 注释列表默认按正文锚点从上到下排列；同一锚点内按创建时间排列。
- 点击注释时滚动并强调正文目标；点击正文高亮时定位右侧对应注释。
- 同一目标存在多条注释时，以一个稳定高亮承载数量提示，避免叠加多层不可辨识底色；最终聚合交互在实现验收时确认。
- 失锚注释不得静默消失，应在注释列表显示可理解的“原文位置已变化”状态。

### 6.3 作者与访客徽标

- 每条评论、注释和回复显示“作者”或“访客”小徽标。
- 徽标由认证系统的已验证邮箱与作者白名单比较后派生，用户不能自行选择。
- 不在前端显示登录邮箱；只显示公开名称、徽标和时间。
- 徽标只表达身份，不引入等级、积分、认证层级或社交关系。

### 6.4 编辑和删除反馈

- 用户只能编辑自己的内容；编辑后可显示轻量“已编辑”提示，不展示历史版本。
- 删除根线程会删除全部回复，执行前必须清楚提示影响范围并二次确认。
- 作者可以删除任意讨论内容，但不能编辑他人的文字。
- 删除为硬删除，不显示墓碑或回收站入口。

### 6.5 讨论内容渲染

- 评论和注释复用统一 `DocumentRenderer`，使用更严格的 `discussion` profile。
- 允许安全 Markdown、代码、表格、KaTeX、严格模式 Mermaid；注册组件还必须进入集中 allowlist，v1 不开放讨论区 Canvas 或问答题。
- 禁止原始 HTML、任意脚本/样式、图片、音视频、SVG/HTML/网页嵌入和任意动态模块路径。
- 遇到禁止组件时在发布前给出明确错误，不静默删除用户内容。

## 七、导出交互

- 导出入口是一级菜单；Markdown 二级菜单提供纯正文、正文+注释、正文+评论、正文+注释+评论。
- TXT、DOCX、PDF 使用相同内容范围选择；问答题可增加“包含答案与解析”开关。
- PDF 点击后直接生成并下载，不调用 `window.print()`、系统打印机或 Windows 打印对话框。
- 生成期间显示可取消的进度状态；失败时说明具体组件或资源，不只显示“导出失败”。
- 含讨论导出必须显示快照时间；讨论读取失败或超过上限时让用户明确选择重试、分卷或仅正文，不得把不完整文件标成“全部导出完成”。
- 导出相关代码动态加载，不进入普通阅读首屏包。

## 八、音效规范

- 全部音效经 `src/lib/audio/` 统一播放，受全局开关（导航挂件）控制，默认**关闭**（尊重访客）
- UI 音效放 `public/sounds/`，单文件短小（<100KB 量级）
- 具体触发点位与素材来源待后续轮次定

## 九、决策理由

- **语义 token**：四主题切换 + 未来自定义主题，只有语义层能做到"换主题不改组件"
- **首页固定视觉**：3D 场景是"作品"不是"界面"，一套精调视觉的品质远高于四套仓促适配；成本降低 75%
- **移动端卡片入口**：移动端跑 3D 的代价（发热/耗电/流量/低端机卡顿）远大于收益，直达内容才是移动场景的真实需求
- **统一 z-index 表**：多浮层产品（导航/面板/悬浮球/弹窗）最易层级打架，提前立表成本几乎为零
- **统一渲染器、不同 profile**：文章和讨论共享能力实现，但用户内容只能调用经过明确允许的安全子集
- **评论与注释分区**：文章级讨论和选区级批注拥有不同入口与排序语义，不能用一个发布类型开关混在一起
