## 一、页面地图

| URL | 页面 | 说明 |

| `/blog/` | 文章列表 | 书架/书屋风（与首页 3D 书的世界观连贯）。视觉与交互 **1:1 对标** [blog-reader-prototype.html](../designs/blog-reader-prototype.html) |

### 预留路由（已确定未来会做，现在留位不实现）

| URL | 板块 | 说明 |
|---|---|---|

| `/works/` | 作品集/项目展示 | 地址已挂上建设中页；正式内容是项目与作品，带演示链接 |

预留规则：
- 新板块一律用**平行一级路由**，不嵌套进 `/blog/`
- 板块内的详情页沿用 `/<板块>/<slug>/` 模式（如 `/works/<slug>/`）
- 绳挂导航桌面端已挂博客 / 随笔 / 作品集；关于我不进绳
- `/about/` 未实现前，对应首页卡片显示“筹备中”并禁用跳转，不链接到 404

## 二、URL 规则

1. **一律小写 kebab-case，尾随斜杠**（`trailingSlash: true` 已配置）：`/blog/three-body/`
2. **文章 slug = 纯英文短链**：每篇文章起一个英文短名，不带年份、不用中文
3. **slug 即文件夹名**：`content/posts/<slug>/` 的文件夹名就是 URL，frontmatter 不另配 slug，一次命名全局一致
4. **全量静态化**：`[slug]` 动态路由必须提供 `generateStaticParams`，构建时枚举 `content/posts/` 生成全部页面；禁止运行时动态路由（export 模式不支持）
5. **URL 一经发布不改**：slug 是分享与外链的锚，发布后重命名需在 `edgeone.json` 配 redirect（不在 `next.config.ts` 配）

## 三、导航项与路由的映射

绳挂卷轴导航（全站共用同一套外壳，以 [blog-reader-prototype.html](../designs/blog-reader-prototype.html) 为模板；首页与阅读页只换挂件内容）：

| 导航项 | 行为 | 是否路由 |
|---|---|---|
| 日夜模式切换 | 就地切换主题 | 否（挂件） |
| 音效开关 | 就地开关 | 否（挂件） |
| 设置 | 就地弹出小面板（主题、音效等） | 否（面板，不设 `/settings/`；设置项增多后再评估升级为页面） |
| 博客 | 跳转 | `/blog/` |
| 随笔 | 跳转 | `/notes/`（建设中占位，正式内容后仍用此地址） |
| 作品集 | 跳转 | `/works/`（建设中占位，正式内容后仍用此地址） |

「关于我」不进绳挂，只留在首页卡片；对应 `/about/` 仍预留、本轮不实现。

首页 `/`、书架 `/blog/`、以及 `/notes/` `/works/` 入口页：桌面绳上同时挂博客、随笔、作品集（常显）。文章 `/blog/<slug>/` 隐藏随笔与作品集，羽升和博客回到阅读页左侧。移动端绳上不挂这三个板块。

阅读页顶部渐隐导航额外含：

- **导出**：悬浮/展开二级菜单，选择 Markdown、TXT、DOCX 或 PDF，并选择正文/注释/评论组合；文件直接下载，不调用系统打印对话框；
- **编辑**：P3 接入后，作者白名单进入渲染/源码模式切换；这是同页状态，不设置编辑路由。P3 前不显示伪可用入口；
- **分享**：见下节。

登录使用弹窗，不设置 `/login/`。访客触发评论、注释或回复写入动作时呼出登录弹窗；真实认证未接入前由身份接口提供明确的未开放状态。

## 四、分享规范

文章 URL 静态且永久（见二.5），分享的基础设施围绕它展开：

1. **分享按钮**（阅读页顶部导航）：移动端优先调用系统分享（Web Share API），不支持时降级为复制链接 + 下落便签通知（全站同一套 toast，禁止另做提示条）
2. **定位分享**：支持带标题锚点的深链 `/blog/<slug>/#章节锚点`，打开后自动滚动到对应章节；标题锚点由规范化标题文本生成，同名标题追加 `-2`、`-3`。不修改标题及同名标题顺序时结果稳定；改标题可能改变深链，不承诺“任意编辑后永不变化”
3. **链接预览（OG 元信息）**：每篇文章通过 `generateMetadata` 输出标题、摘要、封面图，保证链接贴到微信/社交平台时显示卡片而非裸链接；摘要与封面取自文章 frontmatter
4. 分享卡片图（长图/海报）为未来增强项，不在第一期

## 五、路由层代码规则

1. `src/app/` 下的 page.tsx 只做组合（引 feature 组件拼装，<30 行），业务逻辑一律下沉 `src/features/`
2. 移动端首页降级**不是独立路由**：`/` 同一路由内做客户端设备检测（视口/指针类型），渲染 3D 叙事或卡片入口两套组件；两套组件都归 `src/features/home-journey/`
3. 404（not-found.tsx）与 loading 骨架复用阅读页原型的书卷外壳与阻尼动效，不另做系统灰页；未出独立原型前只换文案

## 六、阅读页状态与右侧工作区

评论、注释和未来 Agent 都是 `/blog/<slug>/` 内的阅读状态，不建立子路由：

| 入口 | 目标面板 | 语义 |
|---|---|---|
| 顶部/侧边“评论”入口 | 评论 | 针对整篇文章的评论线程 |
| 划词工具条“注释”入口 | 注释 | 针对当前稳定文本选区的注释线程 |
| 未来“询问”入口 | Agent | 携带选区或文章上下文的 AI 接口外壳 |

- 评论根线程不含文本锚点；注释根线程必须含有效文本锚点。
- 回复继承根线程目标，不产生新路由或新锚点。
- URL 不承载面板开关、登录态或编辑态的长期状态；后续如需可分享的注释定位，再单独定义稳定查询参数/片段协议。
- 导出不建立 `/export/` 公共页面；阅读页直接生成并下载文件。

## 七、决策理由

- **平行一级路由**：各板块可独立开发、独立删除，URL 语义清晰
- **slug 即文件夹名**：避免"文件名与 URL 不一致"的长期混乱
- **移动端不设独立路由**（如 `/m/`）：同一 URL 在任何设备可分享互通，避免双份 URL 的维护与 SEO 分裂
- **分享不需要新路由**：SSG 的 URL 天然稳定可分享，要补的是"分享动作 + 链接预览元信息"，不是路由
- **登录/评论/注释/导出不增设页面路由**：它们是文章阅读上下文中的动作或面板，独立路由只会制造状态同步和分享歧义
