## 问题陈述

为个人博客（Next.js 16 App Router + EdgeOne Pages SSG）制定整体架构：
内容格式与文档引擎、评论体系、首页 3D 叙事、导航/主题等前端统一板块的技术选型与模块划分。
核心诉求：图文并茂 + 交互内容、画词评论并可导出给 AI 修订、全站氛围统一（书卷/宣纸风）。

## 整体架构画像 ✅

```
仓库 MD 文件(正式文章) ──构建时(SSG)──> EdgeOne 静态页面（SEO 好、稳定）
                                            │ 浏览器运行时叠加
Supabase ──────运行时──────> 评论、草稿、在线编辑增量、（未来）登录体系
```

- 部署形态维持 `output: 'export'` 纯静态导出不变
- 动态能力（评论/草稿/编辑保存）全部走 Supabase 客户端直连
- 现存问题：`src/app/api/ping/route.ts` 与 export 模式冲突，后续处理（迁移或删除）

## 决策记录

### D1 评论后端：Supabase ✅

| 候选 | 结论 |
|---|---|
| 浏览器本地存储 | 否——不满足真持久化 |
| EdgeOne 云函数 + KV | 否——存储/查询能力弱，开发量大 |
| **Supabase** | **✅ 采用**——真持久化、自带登录体系、免费额度够用 |

登录体系确定要有，具体方案（谁能评论、用什么方式登录）留待后续轮次讨论。

### D2 内容存放：混合模式 ✅

- 正式文章 = 仓库内文件，构建时打进静态站（SEO 最优）
- 编辑草稿、评论等增量 = Supabase，阅读时客户端叠加
- 在线编辑保存 → 云端草稿；正式发布 → 回写仓库文件重新部署（流程细节待定）

### D3 权威内容格式：MD 内嵌自定义 XML 标签 🔶（方向已定，细节待补充）

**单文件 Markdown + frontmatter 元信息 + 白名单自定义标签 + 大数据外置资产文件。**

```markdown
---
title: 三体运动的混沌之美
date: 2026-08-14
---

# 三体运动的混沌之美

正文……

<sim id="three-body" height="400">
  { "planets": 3, "speed": 1.5 }
</sim>

$$E = \frac{1}{2}mv^2$$

<video-embed src="/media/three-body.mp4" caption="实验录像" />
<chart src="./data/sales-2026.json" />   <!-- 大数据外置，按路径/ID 引用 -->
```

**淘汰的候选**：
- ProseMirror/TipTap JSON 直存：不可读、Git diff 不可用、AI 不擅长直接读写、脱离编辑器无法写作
- MD + 伴生 JSON 双文件：占位符与定义分离易失配；其"好处"拆解后各有更佳归宿（见下）

**"MD+JSON" 直觉的正确拆法**：
1. 文章元信息 → frontmatter
2. 板块大数据 → 独立资产文件，标签内 `src` 引用；小配置直接内联
3. 评论锚点 → **绝不写入文章文件**，存 Supabase（见 D4）

### D4 评论锚定：文字引语锚定（W3C Web Annotation / Hypothes.is 模型）✅

每条评论在 Supabase 记录：`文章 slug + 被画词的文字引语 + 前后上下文片段`。

- 文章小改动：靠上下文模糊匹配自动跟随
- 大改动找不到：评论进入「失锚待认领」状态，提示人工归位
- **导出**：MD 原文 + 按锚点位置插入 `<comment>` 标签 → 生成单份完整文本，直接喂 AI 修订

### D5 文档引擎：渲染器注册表（"像 Agent 工具一样注册渲染模式"）✅

底层用 unified/remark 管线（Markdown 生态事实标准），不自造解析器。
新增一种可视化 = 注册一个标签；渲染、编辑预览、导出、目录提取自动全部支持。
未注册/非法标签安全降级为提示块，不崩页面。

```
src/features/doc-engine/
  registry.ts        标签名 → 渲染组件 注册表
  renderers/
    katex/           <math> 公式
    canvas-embed/    <sim> 画布/交互模拟
    svg-embed/       <svg-figure>
    html-embed/      沙箱内嵌 HTML
    video-embed/     视频
  pipeline.ts        MD 解析管线（白名单标签）
  exporter.ts        MD + Supabase 评论 → 带 <comment> 的完整文本
  toc.ts             标题/板块提取（目录树模式与图形模式共用同一份数据）
```

### D6 在线编辑：渲染 ↔ 源码双模式切换 🔶（方向已定，实现后置）

- 顶部导航点「编辑」→ 页面切为纯文本（MD 源码）可编辑 + 基础保存机制；再点切回渲染模式
- 因权威格式是 MD，无需 WYSIWYG 引擎（TipTap 退场）；未来若要飞书式所见即所得，可引入 Milkdown（MD 为权威格式，存储层不变，后路是通的）
- 第一版大概率不做编辑功能，但**底座需预留**：渲染管线与「模式切换」的状态结构从一开始就按双模式设计

### D7 动画 / 3D 技术栈分层 ✅

| 层 | 用途 | 选型 |
|---|---|---|
| L1 UI 微交互 | 按钮、面板收展、导航渐隐 | CSS transition + Tailwind |
| L2 编排动画 | 滚动叙事总导演、文字效果 | GSAP + ScrollTrigger（3.13+ 全插件免费；附魔台文字 = ScrambleText + 符文字体；文字拆散 = SplitText） |
| L3 3D 场景 | 立体书、翻页、摄像机推进、金光、众妙之门 | Three.js via @react-three/fiber + drei |
| 绳挂卷轴导航 | 绳子摆动 | 轻量 verlet 绳索模拟或 SVG+GSAP，不引入完整物理引擎 |

首页滚动叙事 = 一条 GSAP ScrollTrigger 时间线做总导演，滚动进度驱动 R3F 摄像机与书本动画；
落地页 → 文字拆散汇聚成书 → 摄像机下移书打开翻页 → 金光过门 = **同一条时间线的四个章节**。

性能约束：Three.js/GSAP 全部动态 import 只在首页加载；移动端 / `prefers-reduced-motion` 提供降级版（降级程度待定）。

### D8 组件库与配套选型 ✅

美术风格高度定制（绳挂卷轴、宣纸氛围），不用成品组件库（AntD/MUI 会打架）。

| 用途 | 选型 |
|---|---|
| 无样式交互基座 | Radix UI（shadcn 方式拷源码进 `src/components/ui/`） |
| 目录图形模式 | React Flow（@xyflow/react）——画布 + 小地图 + 点击跳转 |
| 左右栏自由拉动 | react-resizable-panels |
| 全局状态（主题/音效/布局） | zustand |
| 音效 | howler.js |
| 公式 | KaTeX（作为 doc-engine 的一个渲染器） |

### D9 主题系统（"日夜模式切换"）✅

- 导航项「日记页模式切换」为笔误，实际是**日夜/主题切换**
- 预设主题：**宣纸黄（书卷清新，默认）/ 浅蓝 / 米白 / 纯黑**
- 实现：CSS 变量 + Tailwind v4 tokens，切换只改 `<html data-theme="...">`；
  背景、字体、组件配色全部走 token，属于「前端统一板块」，所有组件从第一天起禁止硬编码颜色

### D10 模块划分 ✅

```
src/features/
  doc-engine/     ★ 统一文档内核（见 D5）
  home-journey/   首页 3D 滚动叙事（四章节时间线、R3F 场景、降级方案）
  navigation/     绳挂卷轴导航（首页 + 博客页顶部渐隐导航共用）
  toc/            左侧目录（树模式 + React Flow 图形模式，tab 切换）
  comments/       画词评论（选区捕获、锚定、面板、存储适配层→Supabase）
  agent-shell/    右侧智能体外壳（只做壳，预留接口）
  reader-layout/  博客三栏布局（可收起悬浮球、可拉动分栏）
  settings/       设置页（主题、音效）
src/lib/
  audio/          音效管理
  theme/          主题 tokens
```

关键原则：comments 的存储做成**适配层**，接口固定，底层实现可替换。

### D11 主题作用范围：首页 3D 固定一套视觉 ✅

主题切换只作用于常规页面（阅读页/列表页/面板）；首页 3D 叙事像电影片头，一套精调视觉不随主题变，
避免四套灯光/材质的成本。首页内的 UI 挂件仍走 token 跟随主题。

### D12 移动端首页：直接降级为卡片式板块入口 ✅

移动端不跑 3D、不加载 3D 资源（不只是不渲染）：`/` 同一路由内客户端检测设备，
渲染经典卡片式板块入口（博客/短随笔/作品集/关于我 + 主题与音效挂件）。
移动端用户以读文章为主，入口效率优先。不设 `/m/` 独立路由，保证同一 URL 全设备可分享。

### D13 未来板块与路由预留 ✅

已确定未来会做：`/notes/`（短随笔/唠嗑）、`/works/`（作品集/项目展示）、`/about/`（关于我/电子分身）。
一律平行一级路由，现在留位不实现；绳挂导航与移动端卡片入口预留挂位。

### D14 文章分享 ✅

阅读页顶部导航增加「分享」：Web Share API（移动端系统分享）+ 复制链接降级；
支持标题锚点深链（`#章节锚点`）；每篇文章输出 OG 元信息（标题/摘要/封面）保证微信等平台的链接卡片预览。
无需新路由——SSG 的 URL 天然稳定可分享。详见 [routing.md 第四节](../conventions/routing.md)。

### D15 编辑草稿的云端存储模型：快照 + 基线指纹 ✅

**每篇文章最多一份云端草稿 = 改后全文 + 基线指纹（编辑时所基于正本的校验码）。保存即覆盖，无历史版本。**

- 不做版本控制——需求只有"编辑"，不是 Git
- 不存 diff：diff 方案保存时要多算差异、阅读时要多拼装、正本更新后可能"贴不回去"需要修复逻辑；
  快照方案保存零计算、阅读零拼装（编辑器手里本来就是改后全文）
- 想看"改了什么"→ 拿草稿与正本**现算 diff 展示**，不落库（Git 底层同款思路：存快照，diff 现算）
- 基线指纹的唯一作用：正本更新后能明确提示"草稿基于旧版本"，不默默错乱；成本一个字段
- 存储量无虞：纯文字一篇几十 KB，Supabase 免费额度可存上万份全文快照
- 前期无编辑功能时此模型零成本，后期按此接入

### D16 content/ 与 EdgeOne 部署的兼容性验证 ✅

经查证 EdgeOne Pages 官方构建流程：完整拉取仓库 → 仓库根目录执行 buildCommand → 仅上传 outputDirectory（out/）。
因此根目录 `content/` 构建时完全可读、且不会被暴露到线上——方案无部署风险，维持根目录不进 `src/`。
⚠️ 实现期固定工序：文章文件夹内的媒体（media/）需要构建步骤搬运进 out/ 产物，否则线上访问不到。

### D17 首页活字引擎：Pretext（@chenglou/pretext）✅

用户指定，已查证为真实成熟库（chenglou 出品）。定位澄清：**它不是动画库，是文字测量排版引擎**——
零 DOM 读取，为每个字符算出精确坐标（"家位置"）。与既有三层动画栈的分工：

- **Pretext** 算每个字该在哪（散开前的原位、聚合后的落点、悬浮基线）
- **GSAP** 管时间线与缓动（字何时飞、怎么飞）
- **Three.js / Canvas** 负责画出来

官方生态自带 scatter/gather（散聚）、文字雨、悬浮波浪等示例，与附魔台式散聚需求直接吻合。
使用范围：仅首页叙事的活字效果（散开、汇聚、悬浮书上、游荡、文字雨）；正文阅读页不用它（正常 DOM 排版）。

## 决策理由（总纲）

1. **可读性优先**：作者日常手写 MD，权威格式必须人可读、Git diff 可用、AI 可直接读写
2. **一套内核多处复用**：渲染/编辑预览/导出/目录提取共用 doc-engine 与注册表，新板块零架构成本
3. **静态站 + 云端增量**：SEO 与稳定性靠 SSG，动态能力全部隔离到 Supabase 适配层，互不污染
4. **动画分层不混用**：CSS 管微交互、GSAP 管编排、R3F 管 3D，各层独立可降级
